## Decision Boundary

architecture, implementation correctness, testing, and package identity. It
does not supersede the
[Domain Access Architecture](20260729-v1.0-domain-access-architecture.md)
or the [Materialized Dataset Contract](tidy-dataset-contract.md). It does not

If this review and an approved contract disagree about runtime behavior, the
approved contract remains authoritative until a later versioned successor

as a defect against the approved contract or against this recorded finding.

This review does not authorize package publication, formal snapshot
replacement, or deletion of old artifacts.

## Verdict

`bioextract` is an independent domain-access library: callers supply official
local snapshots; the library hides resource-owned identifiers, joins, and
hierarchies; storage is a strategy (native files or one DuckDB per logical
product). The independence boundary holds in executable code.

The highest-priority defects are honesty defects, not missing resources. The
root README still advertises metadata v1 and deleted `extract_*` terminals.
The development tree version is `0.1.0` while wheels, freeze files, and plans
name `0.5.0`–`0.7.0`. Provenance can therefore record a package identity that
is neither the last release nor the intended tag.

Approximate inspected size: about 31,404 Python lines under `src/bioextract`
and 13,734 under `tests/`.

## Scope And Method

The review read `AGENTS.md`, both READMEs, `docs/README.md`, the domain
architecture, the tidy-dataset contract, publication and runtime modules, and
representative resource adapters (GO, KEGG, Reactome, UniProt, ChEBI, STRING,
eggNOG, OmniPath). Contract tests were used as the lock on the current public
surface.

It is not a full real-snapshot smoke, not a formal-release closeout, and not
an enrichment-analysis review. Incomplete package-release and CephFS
replacement records remain as previously written.

## Product And Architecture

### Strengths

- No downloader, no `biofetch` import, no enrichment p-values in `src/`.
  Runtime dependencies are Polars, DuckDB, and PyArrow.
- Public surface is eleven `*Database` handles plus `inspect_publication`,
  loaded lazily from `src/bioextract/__init__.py`.
- eggNOG, STRING, and OmniPath remain native-file strategies. GO, KEGG,
  Reactome, UniProt, ChEBI, Rhea, WikiPathways, and InterPro publish DuckDB.
- Writers stage, `CHECKPOINT`, reopen/validate, then `os.replace`. Biological
  relations live in `main`; provenance is exactly five `_bioextract` tables.
- Metadata v2 in code rejects `bioextract.sources` and requires paired
  `release_version` / `release_version_source`.
- KEGG organism mapping is a true dual path: shared relation nouns over Polars
  source scans and a DuckDB-native publisher.
- Tests lock the break from the old surface: no `extract_*`, no `read_mapping`,
  no directory/`write_parquet` writers.

## Scientific And Implementation Correctness

### C-1 — Severity: bug

- File: `src/bioextract/go/go.py:605-613`, `src/bioextract/chebi/chebi.py`,
  `src/bioextract/rhea/rhea.py`, `src/bioextract/kegg/metabolic/core.py`
- Description: Directory constructors `rglob("*")` without depth, file-count,
  or byte caps. `AGENTS.md` forbids unbounded recursive walks of `/cephfs_data`.
  GO treats any filename containing `.obo` as ontology input.
- Suggestion: Resolve a concrete subtree, then scan with allowed suffixes, max
  depth, and a result-count cap. KEGG mapping already uses one-level
  `scandir`.

### C-2 — Severity: bug

- File: `src/bioextract/go/ontology/derive.py`
- Description: Hierarchical parents missing from `term` are counted in
  indegree while distance maps are initialized only from term IDs. A dangling
  `is_a` / `part_of` target raises `KeyError` during `write_duckdb` instead of
  `IntegrityError`.
- Suggestion: Reject edges whose endpoints are absent from `term`, and raise a
  typed integrity error.

### C-3 — Severity: bug

- File: `src/bioextract/uniprot/_query.py:836-841`,
  `src/bioextract/uniprot/uniprot.py`
- Description: Shared `normalize_input_id` unwraps `sp|P04637|…`. Reactome,
  STRING, eggNOG, and OmniPath use it. UniProt knowledgebase and idmapping
  selections only strip. Pipe-form accessions become unmatched.
- Suggestion: For `namespace="uniprot"`, reuse `normalize_input_id`.

### C-4 — Severity: bug

- File: `src/bioextract/kegg/kegg.py:230-252`
- Description: `from_duckdb` stores a path only. GO/Reactome/ChEBI pin
  `(dev, ino, size, mtime, ctime)` and refuse a replaced file. Replacing a
  KEGG DuckDB while a handle is live silently changes query results.
- Suggestion: Apply the same publication-identity assert as GO `connect()`.

### C-5 — Severity: suggestion

- File: `src/bioextract/reactome/reactome.py`
- Description: NCBI identifiers are returned after strip only. ChEBI and GtoP
  in the same helper canonicalize. `NCBIGene:7157` versus `7157` unmatched.
- Suggestion: Strip a documented NCBI prefix set or reject invalid forms.

### C-6 — Severity: suggestion

- File: `src/bioextract/_tidy.py:150`
- Description: `resource_name or self.build_id_prefix` contradicts the rule
  that `build_id_prefix` never supplies resource identity. Public writers set
  `resource_name`; the fallback is a provenance footgun.
- Suggestion: Require `resource_name`.

### C-7 — Severity: suggestion

- File: `src/bioextract/_publication.py:761-765`
- Description: Missing install metadata becomes provenance value `"unknown"`.
- Suggestion: Fail publication if the distribution is not installed, or record
  an explicit unresolved key that cannot be mistaken for a release.

## Testing

Contract, unit, and hermetic integration layers match the test standard.
`tests/contract/api/` locks `__all__`, lazy import, and the post-`extract_*`
surface. Atomic replace and metadata v2 rejection are covered.

Gaps aligned with the defects above: UniProt pipe IDs, GO dangling parents,
KEGG publication replacement, bounded directory discovery. Smoke against
host-owned snapshots remains opt-in and is out of this review's execution.

## What Remains Solid

- No `shell=True`. No hardcoded `/home/fqzhang` or `/cephfs` under `src/`.
- User identifiers bind through placeholders or temporary tables. Interpolated
  SQL names pass `_SQL_IDENTIFIER` or come from internal schema maps.
- Extra metadata cannot overwrite canonical publication keys.
- Unmatched-ID accounting exists on GO, ChEBI, and KEGG mapping with reason
  codes.
- Filename is not schema identity.

## Out Of Scope

This review does not authorize a new resource adapter, enrichment statistics,
generic query facade, CephFS publication, or converting the Reactome v0.5 /
formal-release remaining gates into passes.
