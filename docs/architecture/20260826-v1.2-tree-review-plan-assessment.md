## Verdict

v1.1 is a real contract correction, not a softening of the original findings.
Withdrawing Reactome NCBI rewriting, removing UniProt pipe handling from exact-
text boundaries, splitting GO false-suffix bugs from directory-discovery
policy, and keeping GO table-name remap as documentation rather than a schema
change all match current authorities. The successor plan must amend each
selected UniProt-capable owner before claiming one uniform pipe contract.

The assessed v1.1 plan could start with its documentation-only Unit 0. Its Unit
1 was the dangerous part: it was not “add two strip calls to UniProt.” Shared
input-frame helpers currently apply UniProt pipe parsing to both single and
grouped selection callers. Rhea’s independent pipe grammar is not the same as
`_shared.normalize_input_id`, and some APIs use UniProt accessions without
naming their namespace `uniprot`. Those facts are now frozen in Slice 3 of the
successor plan.

The adversarial review completed after this assessment was drafted and is
incorporated into the linked v1.2 plan. It confirmed that pipe handling is a
mandatory caller-input contract at selected UniProt-capable boundaries, not an
optional cleaning flag and not official source-data cleaning. It also replaced
the coarse Unit 0–3 sequence with four delivery slices and replaced a static
next-development version choice with SCM-derived development builds, nightly
artifacts, and an explicitly authorized final release path.

## Remaining Inaccuracies In v1.1

### 1. Rhea and shared pipe grammars differ and neither is frozen

Rhea (`src/bioextract/rhea/_query.py:1213-1219`) accepts any string containing
`|` with a non-empty second field and takes that field. Shared
`RE_UNIPROT_PIPE` requires a second pipe, but it is a prefix match: it does not
restrict the database token to `sp`/`tr`, require a non-empty entry-name field,
or reject extra fields.

```text
sp|P04637|P53_HUMAN  -> both yield P04637
foo|P04637           -> Rhea accepts; shared regex leaves the string unchanged
foo|P04637|          -> both yield P04637
foo|P04637|name|x    -> both yield P04637
```

The plan’s “one private UniProt helper reused by Reactome and Rhea” is right
only after the legal pipe form is written down. The target contract should
accept a plain trimmed accession and full `sp|accession|entry_name` or
`tr|accession|entry_name` forms with non-empty fields. Other pipe-bearing forms
fail explicitly. This intentionally tightens undocumented permissive inputs
and therefore needs owning-contract and rejection tests before helper reuse.

### 2. Literal `namespace="uniprot"` is too narrow, but capability is not yet declared everywhere

UniProt capability is owned by each public selection boundary, not only by a
parameter spelling. InterPro accepts UniProt accessions directly; OmniPath
`namespace="protein"` and STRING alias/string selection currently document
the shared normalization behavior. Conversely, eggNOG protein IDs and
WikiPathways Entrez Gene IDs are exact-text identifiers. This does not mean
every semantic UniProt boundary already promises pipe form: InterPro, UniProt,
and Rhea contract text must be amended with the behavior. The plan must use an
explicit caller matrix rather than infer behavior from the namespace label or
from incidental shared-helper reuse.

### 3. GO lazy/eager wording is still split across docs

Domain architecture records the closure exception. `go-kegg-tidy.md:85-91`
still describes publication-backed ancestor selection as materializing final
eager frames, while current terminals are `ancestors()` / `unmatched_ids()`
returning `LazyFrame`. P-6 is not overturned. The v1.1 plan left placement
between Unit 0 and Unit 3; the successor plan assigns this correction to
Slice 1.

### 4. C-2 does not name the source error type

Implementers must not invent a third exception. Source-backed malformed OBO
should stay `ValueError` (or the existing source constructor errors).
Reopened-publication identity failures stay `IntegrityError`.
`IntegrityError`’s docstring currently also mentions source integrity; do not
broaden it during the integrity slice.

These leftovers do not restore the withdrawn NCBI finding.

## Plan Execution Risks

### The identifier slice is a cross-resource change

`create_input_id_frame` and `create_group_input_frames` always call
`normalize_input_id`. Their current caller policy is:

| Caller | Owning input contract | Target normalization |
| --- | --- | --- |
| eggNOG | exact eggNOG protein ID | trim only |
| InterPro | UniProt accession | UniProt pipe or plain accession |
| STRING `alias` | alias text; current docs allow UniProt pipe input | strict UniProt pipe or existing non-pipe alias text, then alias lookup |
| STRING `string` | exact STRING protein ID | trim only |
| OmniPath | protein ID; current docs allow UniProt pipe input | UniProt pipe or plain protein ID |
| WikiPathways | Entrez Gene ID | trim only |
| KEGG mapping | `uniprot`, `ncbi_gene`, or `kegg_gene` | normalize in the declared namespace first; the shared frame builder only trims |

Changing the helpers affects observable behavior only for pipe-bearing values,
but it affects both single and grouped APIs. Negative controls must land on
actual exact-text callers such as eggNOG and WikiPathways and on KEGG's
non-UniProt namespaces, not only on the private helper.

The complete accepted matrix additionally applies the strict helper to
UniProtKB single/grouped and UniProt idmapping single selection only for
`namespace="uniprot"`, to Reactome/Rhea `namespace="uniprot"`, to InterPro
selection, to OmniPath `namespace="protein"`, and to STRING
`namespace="alias"`. UniProtKB's `entry_name`, `gene_name`, `gene_id`,
`refseq`, `ensembl`, and `isoform_id` namespaces remain under their existing
rules. Idmapping grouped selection remains unsupported. There is no public
normalization toggle.

### Freeze UniProt pipe syntax before merging helpers

Target contract for the identifier slice:

```text
Valid plain form: accession
Valid pipe forms: sp|accession|entry_name or tr|accession|entry_name
All fields are non-empty; the complete input must match.
```

Plain non-pipe values retain the current lookup/unmatched behavior; this slice
does not add a separate UniProt accession-syntax validator.

Rhea’s two-field `a|b` form and the shared helper's arbitrary database, empty
entry-name, and extra-field forms are rejected with focused test updates. Do
not “parse whatever has a pipe,” and do not silently retain an invalid pipe
value as a plain accession or unmatched identifier. This rule applies to
caller-supplied selection values. Official source files remain under each
resource adapter's parser contract. The canonical accession becomes public
`input_id`; this remediation does not add `raw_input_id`.

### Discovery policy must not gate C-1A

GO suffix allow-list (`C-1A`) can land immediately. Per-resource layout
inventory and optional depth/count/byte limits (`C-1B`) are a
separate contract. Default: this plan does not introduce a runtime hard cap
unless a resource architecture records official layouts and a failing fixture
that the cap would have caught.

### Four delivery slices keep unlike risks separate

README truth, package/release harnesses, cross-resource identifiers, and
GO/KEGG integrity have different reviewers and evidence. Each slice lands its
own contract and tests. The identifier and integrity slices have little
coupling and may proceed independently after their contract text is included;
the identifier slice must remain isolated enough to cover every shared-helper
caller.

### `pdm run check` timing

Crossing public docs, identifiers, publication lifecycle, build metadata, and
repository workflows justifies a combined gate after all four slices. The
documentation-only Slice 1 does not need CephFS smoke. The package/harness
slice requires `pdm run check`, distribution checks, and a fresh-installed-
wheel probe.

### Package identity and release evidence need separate paths

The post-`0.7.0` tree contains a Reactome behavior fix, so local publication
provenance must not remain the unrelated static `0.1.0`. Tagged release builds
already run `scripts/sync_release_version.py`, so the evidence does not show
that released wheels report `0.1.0`; it shows that development/editable builds
lack a reconstructable identity and that tag creation is coupled directly to
external publication.

The accepted target is PDM SCM dynamic versioning. Pull-request/main CI builds
and tests without publishing. A scheduled nightly builds and fresh-installs a
PEP 440 development wheel from a clean main checkout, retains a finite-lived
artifact, and does not touch PyPI, CephFS, or the formal real-snapshot path. A
dirty source tree may run editable development and tests but must fail before
creating a wheel or sdist. External `rcN` publication is explicit. Final PyPI
publication follows a published GitHub Release for a verified tag through a
dedicated Trusted Publishing workflow and protected environment; a tag push
alone is not release authority.

The final upload job accepts only a non-prerelease `release.published` event,
requires a canonical final `X.Y.Z` tag, checks out that release's tag
explicitly, and verifies the tag-to-commit and distribution identity. An
explicitly published GitHub prerelease has its own guarded, protected-
environment path and also requires a canonical `X.Y.ZrcN` tag with positive
`N`. Both upload jobs check out the event's exact release tag, resolve its
commit, reject a dirty or mismatched tree, parse and canonicalize the tag, and
assert both the expected PEP 440 release kind and exact distribution identity.
Tag-push and manual-dispatch paths are build-only and hold no upload permission.
Workflow review must prove no second PyPI upload route remains.

Failing a new publication when install metadata is unavailable changes public
error behavior. Amend the Materialized Dataset Contract and add fail-before-
mutation tests for the shared and Rhea writers. Existing metadata-v2 files with
literal `"unknown"` remain readable but unresolved; do not use them as
compatibility evidence and do not bump the metadata schema solely for this
migration. The literal is the observable unresolved sentinel and fails formal
delivery preflight. Formal database publications must run from a fresh
installation of the exact wheel, not an editable checkout; a temporary
publication reopened through the public inspection path must report a package
version exactly equal to the installed wheel metadata.

## Recommended Plan Amendments

These amendments are incorporated into the linked v1.2 plan. They are not
themselves runtime authority.

1. Deliver README and historical-document truth as a documentation-only slice.
2. Deliver SCM package identity, nightly installed-wheel evidence, protected
   final release, new-writer fail-closed provenance, legacy-reader
   compatibility, and exact-wheel formal publication policy as one package/
   harness slice. Dirty trees do not build distributions; final and RC jobs
   independently validate canonical tag grammar and release kind. Repository
   changes do not themselves configure GitHub/PyPI control-plane protection.
3. Deliver the complete caller matrix, strict full pipe grammar, canonical
   public `input_id`, no normalization toggle, and single/grouped negative
   controls as one cross-resource identifier slice.
4. Deliver GO suffix/dangling-edge fixes, all-profile KEGG file-identity
   protection, and local hygiene as one integrity slice. Add no generic runtime
   traversal cap; later resource-owned limits require a concrete fixture and
   contract.

## What Must Not Be Reopened

- Reactome `ncbi` exact-text after trim.
- Treating UniProt representation parsing as official source-data cleaning.
- A public normalization toggle or a new `raw_input_id` column in this slice.
- A metadata-v1 reader to make the current README true.
- GO frame/table rename without a successor schema.
- Treating `"unknown"` in existing DuckDB files as scientific identity.
- Rejecting an existing metadata-v2 file solely because its historical package
  value is `"unknown"`.
- Publishing nightly artifacts to PyPI or using editable code for a formal
  database publication.
- Building a wheel or sdist from a dirty source tree.
- Treating a GitHub Release prerelease flag as sufficient version-kind
  validation.

v1.1 did not drop a real defect. NCBI withdrawal is contract obedience. The
UniProt finding is stronger than in v1.0 because it now includes the shared
helper misuse.

## Start Work

Start with the documentation-truth slice. The package/harness slice next amends
the Materialized Dataset Contract with its writer and reader tests. The
identifier and integrity slices may proceed independently once their owning
contract edits are included with the implementation.

Do not treat the identifier slice as a UniProt-only strip. It is a cross-
resource caller-input contract convergence. Do not treat the nightly path as a
release: it is reconstructable installed-wheel evidence only.
