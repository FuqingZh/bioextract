# Cross-Resource Execution And Publication Performance Convergence Plan

Version: v1.0
Date: 2026-08-14
Status: P0-P5 bounded execution complete; the P5a Rhea-anchor candidate passes
the v2-compatible gate, while formal release-scale publication acceptance
remains separate
Target: next pre-v1 compatibility release candidate; package release and formal
publication replacement remain separately authorized

## Outcome First

bioextract will keep its native `polars.LazyFrame` public relation contract and
converge the private execution and publication paths that still over-read,
repeat selection work, or materialize complete high-cardinality relations.

The convergence is deliberately not "make every database use one streaming
implementation." It establishes one execution contract with four physical
strategies:

1. native Polars scans for regular source files;
2. DuckDB SQL to Arrow record batches for publication queries;
3. typed parser-to-Arrow batches consumed by DuckDB for custom source formats;
4. explicit materialization for small or inherently global algorithms.

Resource modules continue to own biological parsing, SQL, identifiers, species
and taxon semantics, and relation schemas. Shared private code owns only scan
negotiation, replayable lifecycle, typed batch delivery, and publication
loading mechanics. bioextract does not become a generic query facade.

The plan also introduces a cross-cutting execution-integrity gate. It prevents
an implementation from appearing compliant by returning a `LazyFrame` while
still reading everything eagerly, applying projection or selection only after
the full scan, truncating biological output, weakening diagnostics, or changing
the benchmark workload. The gate constrains outcomes and ownership boundaries;
it does not freeze one SQL spelling, engine, or reversible implementation path.

### P5a bounded follow-up result

The follow-up replaced repeated Rhea input-to-reaction SQL with one
thread-safe, selection-owned compact anchor, short-circuits empty anchors before
downstream selection registration, and registers the compact anchor through a
DuckDB Arrow boundary. It does not add a public execution parameter, persistent
index, or new publication table. The bounded checks were:

1. Rhea backend five-run median: 3.86 s wall and 26.40 s CPU after the

2. full downstream-shaped five-run median: 8.30 s wall, 54.33 s CPU, and

3. all six stable biological artifact hashes identical across repetitions; and
4. no change to the fixed input scope, catalog selectors, formal resources, or

The 11,782-organism build, formal v2 publication rebuild, downstream contract
update, package release, and CephFS replacement remain separate authorized
actions. Any further optimization must retain the same bounded workload and
output reconciliation; it must not use the old wall-time regression as a reason
to introduce public limits, a hidden eager path, or an un-gated index/spool.

## Goal

The implementation must:

1. make column, predicate, selected-ID, and slice constraints reach the physical
   producer when they can be applied safely;
2. share a compact normalized match set across relations created from one
   selection;
3. stop empty selections before opening downstream biological relations;
4. replace high-cardinality deferred-eager queries with bounded, replayable
   batch execution;
5. let custom parsers feed DuckDB through typed Arrow batches without mandatory
   complete-DataFrame or redundant Parquet shuttles;
6. retain explicit materialization where the algorithm genuinely requires a
   global view;
7. add evidence-based selected-ID access for UniProt idmapping without changing
   full-scan semantics;
8. preserve KEGG mapping's accepted three-table aggregate publication unless a
   later query benchmark independently justifies a serving index; and
9. make the execution and diagnostic invariants mechanically auditable without
   encouraging suppression or checker weakening.

## Non-Goals

- No public `max_rows`, `batch_size`, memory limit, thread count, pagination,
  or implicit truncation parameter.
- No bioextract wrappers around Polars `collect()`, `collect_all()`,
  `collect_batches()`, or `sink_*()`.
- No generic SQL, expression compiler, query builder, or public DuckDB table
  facade.
- No requirement that GO graph closure, small BRITE/XML indexes, or another
  inherently global algorithm pretend to stream.
- No default flat `input_id × reaction × every UniProt protein` result.
- No implicit union of external reaction cross-references and UniProt mappings.
- No new persistent normalized KEGG lookup table or ART index without the
  separate query-performance gate in this plan.
- No `manifest.lock`, `biofetch`, automatic download, or source-content hashing
  dependency.
- No formal CephFS publication build, replacement, deletion, package publish,
  or downstream application migration in these implementation slices.
- No hidden scorer in the normal repository CI. Transparent contract tests and
  independent review protect ordinary engineering work; a malicious writer is
  an external control-plane concern.

## Preserved Contracts

### Public relations

- Behaviorally public biological relation methods return native
  `pl.LazyFrame` objects.
- A returned frame owns a frozen, replayable query description. It does not
  borrow an open connection and does not require a `with` block.
- Callers compose relations with Polars and decide when to materialize them.
- `collect_schema()` does not execute the biological query.
- Internal batch boundaries never change biological completeness.
- Top-level row order remains unspecified unless a resource contract explicitly
  states otherwise; callers sort when order is required.

### Biological semantics

- WikiPathways species scope constrains both pathways and pathway-gene
  membership, preventing cross-species Entrez Gene ID matches.
- Rhea input matches, reaction-to-UniProt mappings, external xrefs, and nested
  neighborhoods remain distinct relations with preserved lineage.
- InterPro Pfam results retain `input_id`, `uniprot_id`, `pfam_id`, `pfam_name`,
  and the accepted source trace.
- KEGG mapping retains `organism`, `gene_annotation`, and `ko_annotation`,
  including its accepted `List(Struct)` null/empty semantics and direct versus
  KO-derived pathway distinction.
- Publication metadata v2 describes resolved logical input membership; it is
  not a per-read audit log and does not require per-file SHA-256.

### Errors and lifecycle

- Invalid arguments and known missing capabilities fail immediately.
- Source, publication, parser, and engine failures may remain deferred until a
  Polars terminal executes the plan.
- Replacement of a pinned source or publication produces the existing
  integrity error and requires reopening the handle.
- Success, failure, early `head()`, cancellation, and abandoned iteration close
  readers, connections, stage files, and private temporary resources.
- Resource exhaustion fails the staged operation; it never produces a partial
  result or replaces the previous publication.

## Industry Alignment

The plan follows the execution boundaries used by the installed engines:

| Mature pattern | Application in bioextract |
| --- | --- |
| A lazy source receives requested columns, predicate, row limit, and a batch hint | The private Polars IO adapter forwards an internal scan request to the resource producer. |

| Query engines own filtering, projection, joins, and set transforms | Resource-owned DuckDB SQL applies supported domain filters and explicit projections. |
| Common subplans can be executed once when plans share a pure source | Safe replayable sources use Polars purity and selections share one compact anchor. |
| Blocking operations are explicit and resource-bounded | GO closure and partitioned KEGG nested aggregation remain declared materialization boundaries. |
| Point indexes are workload-specific accelerators | ART or a private lookup relation is evaluated only after query rewrite and profiling fail the accepted budget. |

## Unified Execution Model

### Four physical strategies

| Strategy | Use when | Examples | Materialization rule |
| --- | --- | --- | --- |
| Native Polars scan | Source is regular CSV/TSV/Parquet and Polars can scan it directly | STRING, OmniPath, UniProt idmapping source, InterPro protein2ipr | Let Polars own projection, predicate, and slice pushdown. |
| DuckDB SQL to Arrow | A publication or normalized relation is best queried relationally | Rhea, Pfam, WikiPathways, KEGG mapping, UniProt publications | Open a fresh connection per execution and stream typed record batches. |
| Parser to Arrow to DuckDB | Official custom format needs Python domain parsing before relational loading | UniProt DAT, GMT, OBO, XML, SDF, KEGG records | Parser yields typed batches; DuckDB consumes them without a complete frame. |
| Explicit materialization | Correctness or the algorithm needs the whole small/global structure | GO topology/closure, small BRITE/XML lookup, compact selection anchor | Name and bound the materialized state; do not present it as streaming. |

An implementation may move a resource between these strategies when fresh
evidence supports it. It must keep the same public relation, schema, error,
lifecycle, and benchmark acceptance surfaces.

### Private relation scan request

Replace the current batch-only producer callback with one private request
object, provisionally:

```python
@dataclass(frozen=True, slots=True)
class _RelationScanRequest:
    columns: tuple[str, ...] | None
    predicate: pl.Expr | None
    n_rows: int | None
    batch_size: int | None
```

The type and the Polars plugin integration remain private. Resource producers
receive one request per execution and open their resources inside that
execution.

The adapter applies these rules:

1. Add predicate root columns to the physical projection even when the caller
   did not request them in the final output.
2. Push explicit columns into native scans or a resource-owned DuckDB `SELECT`.
3. Compile only resource-owned domain filters, including IDs, species, taxa,
   namespaces, and capabilities, into SQL.
4. Do not implement a generic Polars-expression-to-SQL compiler.
5. Apply any residual Polars predicate to each batch as a correctness backstop.
6. Push `LIMIT` into the producer only when no residual predicate can remove
   rows before the requested count is reached.
7. Reapply the final filter, slice, and projection at the adapter boundary when
   needed to preserve correctness.
8. Treat `batch_size` only as an internal throughput hint. It cannot omit,
   split, reorder semantically ordered nested values, or otherwise change rows.
9. Validate typed emitted schemas and close the producer iterator in `finally`.

### Replayability and purity

Every execution opens a fresh reader and verifies the pinned source or
publication identity. The returned frame captures immutable inputs and query
description, not a live cursor.

Set the Polars IO source `is_pure=True` only when:

- the source is replayable;
- identity replacement is checked;
- the relation has no time-, random-, or process-state-dependent behavior;
- repeated execution is semantically identical; and
- focused common-subplan tests prove that purity does not skip required domain
  work or cleanup.

Purity is not the only sharing mechanism. Different public relations may
produce distinct opaque IO nodes even when they depend on the same match set.

### Explicit materialized boundary

Rename or remove `register_deferred_frame_source()`. A fallback that constructs
one complete `DataFrame` must have a name that states materialization and may be
used only by reviewed small/global paths.

High-cardinality relation methods may not hide behind the materialized
fallback. The allowlist is behavior-based and tested; it is not a general
escape annotation.

## Selection Execution And Compact Anchors

Each selection owns one normalized anchor:

```text
input or group membership
    -> normalized input_id
    -> matched canonical entity
```

Examples include `input_id -> rhea_id`, `input_id -> pathway_id`,
`input_id -> primary_accession`, and `input_id -> kegg_gene_id`.

The anchor contract is:

- it contains only caller lineage and canonical match identity;
- it does not contain expanded reaction participants, all related proteins,
  pathways, ontology closure, or other child relations;
- it is computed at most once for a selection execution bundle;
- an empty anchor returns typed empty relations without opening downstream
  tables or parsers;
- it is safe for repeated collection and concurrent `pl.collect_all()` use;
- group fan-out happens only where a public relation requires input lineage;
  normalized resource edges remain unexpanded where their contract permits;
- any memoization is private, bounded by anchor cardinality, thread-safe, and
  released with the selection object.

Use the same pure Polars subtree where plans can share it natively. Where
resource-owned DuckDB queries remain opaque separate sources, use a
selection-owned once-only compact anchor rather than caching expanded relation
results.

Callers continue to use native Polars:

```python
matches, reactions, unmatched = pl.collect_all(
    [
        selection.matches(),
        selection.reactions(),
        selection.unmatched_ids(),
    ]
)
```

bioextract does not add a public relation-bundle collector.

## UniProt Idmapping Selected Access

The production baseline now satisfies the predecessor's evidence gate: scanning
203,130,941 rows costs about 11.7 CPU seconds to return three selected IDs, and
projecting one column costs essentially the same as all 22 columns.

Therefore idmapping source and publication handles extend the existing
database method:

```python
selection = database.select_ids(
    ids,
    namespace="uniprot",
    taxon_ids=[9606],
)

mapping = selection.mappings()
unmatched = selection.unmatched_ids()
```

Public decisions:

- `scan_mapping(taxon_ids=...)` remains the full-scan/analysis relation.
- `select_ids(...)` becomes available on idmapping handles as well as the
  current knowledgebase publication handle.
- The first idmapping selection supports only the controlled namespace
  `"uniprot"`. It does not accept an arbitrary column name.
- The idmapping handle returns a mode-specific selection object exposing
  `mappings()` and `unmatched_ids()`; its concrete class remains a behaviorally
  public return type rather than a stable package export.
- `mappings()` returns `input_id, input_namespace` followed by the existing
  22-column idmapping schema.
- `unmatched_ids()` returns `input_id, input_namespace, reason`.
- Taxon scope participates in the match query. An identifier outside the
  selected taxa is unmatched rather than joined and filtered only after
  expansion.
- Grouped idmapping selection and additional mapping namespaces remain
  evidence-gated follow-ups; this slice does not silently generalize them.

The physical plan registers selected inputs as one Arrow or Polars temporary
relation and joins it inside DuckDB. It does not build a Python `IN` string or
execute one query per ID.

First compare direct query rewrite, physical ordering/zonemap behavior, and
selected projection. Create a single-column ART index only when
`EXPLAIN ANALYZE`, repeated latency, build RSS, build time, and publication size
prove that the index is worth its cost. An index is a physical publication
change and requires updated inventory and rebuild evidence before release.

## KEGG Mapping Query Policy

Keep the accepted three aggregate biological tables. Reverse lookup first uses:

```text
selected external IDs
    -> temporary input relation
    -> read only the requested namespace list column
    -> SQL UNNEST
    -> join to selected inputs
```

Do not add a fourth normalized table merely because an aggregate lookup can be
written relationally. Evaluate a private acceleration relation or ART only if
the rewritten selected query still misses the recorded operational budget.

The KEGG publisher continues to use:

- explicit bounded multi-file role lists;
- DuckDB-native scans;
- private organism/key partitions for `list` aggregation;
- deterministic ordering inside nested lists only;
- internal thread, memory, temporary-directory, and cleanup bounds; and
- the fixed 1,000-organism development scope.

No optimization development run may silently substitute a new organism scope
or rerun the 11,782-organism source. One later full build is a release-readiness
gate after a candidate is frozen.

## Publication Loading Convergence

### Shared writer responsibility

The shared publication boundary continues to own:

- destination validation and `if_exists` behavior;
- a target-adjacent stage;
- metadata schema and source inventory;
- column mapping and validation evidence;
- final relation validation;
- checkpoint, close, cleanup, and atomic replacement.

It does not require every relation to travel through the same temporary
Parquet file.

### Private load strategies

Each relation chooses one private strategy:

1. **native scan/load** for regular source files and multi-file datasets;
2. **Arrow stream load** for typed Python parser batches registered directly
   with DuckDB;
3. **Parquet spool** only for a measured multi-pass, recovery, blocking sort,
   or engine-compatibility need; and
4. **materialized load** for bounded small/global derived relations.

These strategies are not public configuration. A resource writer selects its
strategy from source shape and algorithm, and tests the same publication
contract regardless of strategy.

Set `preserve_insertion_order=false` only where physical row order is not a
contract. Keep local ordering inside order-sensitive nested aggregates.

### Resource priorities

| Resource/path | Current useful foundation | Planned convergence |
| --- | --- | --- |
| Rhea publication queries | Parameterized SQL and Arrow batches | Adopt request-aware projection; make row insertion truly bounded instead of `list(rows)`. |
| InterPro Pfam | Replayable Arrow batch source | Move third-party typing into the shared typed adapter and adopt request-aware projection. |
| UniProt idmapping | Native source scans; publication Arrow batches | Add selected access, projection, empty short-circuit, and compact anchor. |
| WikiPathways publication | SQL species scope and Arrow batches | Adopt request-aware projection; make GMT source parsing batch-capable. |
| KEGG mapping | Accepted DuckDB-native publisher and Arrow publication query | Rewrite reverse selection before considering a serving index. |
| UniProtKB | Complete publication schema and domain relations | Replace deferred eager relation fetches and reduce DAT/FASTA intermediate passes. |
| KEGG metabolic | Stable record parser and domain relations | Replace high-cardinality deferred frame queries; stream parser batches into the publication path where measured. |
| ChEBI | Stable selection semantics and publication | Replace large `fetchall()` relations with Arrow query batches; preserve global traversal semantics. |
| Reactome | Regular source relations and stable publication | Prefer native scans/loads instead of collect-to-frame paths. |
| InterPro general mapping | Native protein2ipr scans available | Remove eager publication queries and centralize Arrow typing. |
| STRING, OmniPath, eggNOG | Native scans already cover major source paths | Preserve native scans; optimize only measured deferred relation paths. |
| GO and small BRITE/XML indexes | Correct global topology and compact lookup behavior | Keep explicit materialization unless a benchmark identifies a real scale failure. |

## Execution-Integrity Anti-Bypass Gate

The integrity gate is cross-cutting. It is implemented alongside P0-P5 rather
than as a later cleanup phase.

### Allowed rerouting

An implementer may revise a planned private mechanism when evidence shows a
better path, provided the replacement passes all preserved contracts,
behavioral probes, output reconciliation, and benchmark gates. In particular,
switching among native scans, Arrow streams, a justified Parquet spool, or an
explicit materialized algorithm is allowed.

### Prohibited bypasses

| Bypass | Examples |
| --- | --- |
| Diagnostic weakening | New unexplained ignore, `Any` escape, lower Pyright/Ruff setting, broader exclude, file/module/project disable. |
| Fake laziness | Returning a `LazyFrame` whose producer immediately constructs one complete `DataFrame`. |
| Late-only pushdown | Reading all rows and columns before applying selection, projection, predicate, or `head()`. |
| Fake sharing | Recomputing matches for every relation or caching a fully expanded child relation. |
| Output truncation | Internal `head()`, public `max_rows`, dropped batches, changed organism scope, or treating resource limits as row limits. |
| Storage substitution | Adding a permanent lookup table, index, or giant mandatory spool without its accepted evidence gate. |
| Semantic substitution | Cross-species ID matches, implicit relation union, restored Cartesian expansion, or source/publication drift. |
| Lifetime borrowing | Returning a plan that depends on an already-open connection or requires the caller to retain a context manager. |
| Benchmark gaming | Comparing different inputs, keeping only the fastest run, ignoring output drift, or using cache hits as proof of pushdown. |

### G0: diagnostic integrity

The initial repository observation found about 106 suppression-bearing lines in
`src/` and 33 in tests/scripts. These counts are an audit starting point, not a
failure threshold and not a permanent allowlist.

Classify each affected diagnostic by contract owner:

1. repair first-party interfaces and module ownership;
2. contain incomplete Polars, DuckDB, or Arrow typing in the narrow shared
   typed adapter using concrete protocols and runtime compatibility tests;
3. replace test-only private access with a private probe seam where practical;
4. retain a source suppression only when no boundary can express a demonstrated
   valid contract.

Every retained suppression names one exact diagnostic and a reviewable reason.
Reject blanket weakening, unused suppressions, `cast(Any, ...)`, and an
unexplained increase. Do not globally prohibit every `Any`: an external
library boundary must instead keep unknown typing from escaping into
first-party resource code.

### G1: static execution-integrity check

Add one repository-owned AST-based checker, provisionally
`scripts/check_execution_integrity.py`, and invoke it from `pdm run check`.
Use syntax inspection only for high-confidence mechanically decidable rules:

- Polars `register_io_source` appears only in the shared private adapter;
- public database and selection signatures do not add public execution limits
  or collection wrappers;
- removed deferred-eager entrypoints do not reappear on high-cardinality paths;
- publisher batch helpers do not materialize an input iterator with `list()`;
- strict type/lint configuration is not weakened globally; and
- accepted source suppressions remain precise and mechanically discoverable.

Do not ban `.collect()` or `.fetchall()` across the repository. Metadata,
schema checks, scalar validation, compact global algorithms, examples, and
tests legitimately use them. Dynamic probes decide whether a public relation
over-materializes.

### G2: dynamic behavior probes

Create test-only producers that record:

```text
requested columns and predicate
requested n_rows and batch hint
opened readers and relations
yielded batches and decoded rows
reader and connection close events
anchor execution count
```

The contract suite must prove:

- relation construction performs no I/O;
- the parser has not reached EOF when its first batch is yielded;
- one-column selection reaches the producer with only required columns;
- `head(1)` does not request a second batch and closes the reader;
- a residual predicate does not make a pushed SQL limit truncate valid rows;
- frames remain replayable after database and selection variables leave scope;
- empty anchors open zero downstream relation readers;
- `pl.collect_all()` computes a shared anchor once;
- cached state contains only the compact anchor;
- a publication loader lets the engine consume a one-shot source batch by
  batch without first constructing a complete Python relation or unbounded
  prebuffer; and
- source and reopened publication fixtures retain identical species, taxon,
  lineage, null/empty, and unmatched semantics.

### G3: performance evidence integrity

Every performance comparison records:

- source/publication identity, selected organism or identifier scope, file
  count, and available input bytes;
- commit, dependency versions, thread settings, and relevant DuckDB settings;
- complete schemas, row counts, relation checksums, and downstream contract
  hashes;
- wall, CPU, first-batch latency, and child-process peak RSS;
- producer columns, batches, decoded rows, relation opens, and anchor calls;
- all measured repetitions, with cold and reused-cache runs distinguished; and
- `EXPLAIN ANALYZE` evidence where a DuckDB physical-plan claim matters.

Do not calculate routine per-file source SHA-256. The existing normalized KEGG
organism-list digest identifies the fixed benchmark scope; publication source
inventory, counts, bytes when already measured, and output reconciliation
protect the workload boundary.

A faster candidate with different output is invalid. Wall time alone cannot
prove pushdown or sharing; corresponding physical counters must change in the
expected direction.

### G4: gate self-protection

The execution-integrity gate owns synthetic negative fixtures. The static
checker or the corresponding dynamic contract must reject:

- a complete-frame lazy producer;
- an ignored projection request;
- `list(rows)` in a claimed batch writer;
- a large `fetchall()` relation hidden behind a lazy wrapper;
- an unexplained type suppression or weakened checker configuration;
- public `max_rows` or a collection forwarding method;
- a benchmark-side `head()` or changed fixed scope; and
- source/publication species-filter drift.

Changing the integrity checker is allowed, but the change must keep existing
negative fixtures failing and add a focused fixture for each new or replaced
rule. Checker, Pyright/Ruff configuration, CI, negative fixtures, and benchmark
harness changes require independent review on the exact head.

This is ordinary repository integrity, not an adversarial security boundary.
A writer able to change both product code and required CI can defeat an
in-repository checker; branch protection, required review, and any externally
trusted checks remain platform-owned controls.

## Performance Acceptance Rules

- Correctness is a prerequisite. A candidate with different rows, schemas,
  nested edge content, capabilities, or downstream outputs has no valid speed
  result.
- CPU is the primary relation-level signal for repeated hidden work; wall time
  is secondary at that layer.
- First-batch latency and producer counters decide whether a path is genuinely
  incremental.
- Child-process peak RSS, not in-process cumulative `ru_maxrss`, decides memory
  claims.
- Projection acceptance requires reduced physical columns or decoded bytes,
  not merely a similar wall time.
- Shared-selection acceptance requires one anchor execution for the measured
  bundle.
- Empty-selection acceptance requires zero downstream reader opens.
- Scale-up RSS should approach a bounded plateau appropriate to batch and
  blocking state rather than track the complete expanded result.
- Report every repetition and explain filesystem/cache variance. Do not select
  the fastest run as the result.
- Do not set one universal percentage target before P0 measures the noise floor.
  Each benchmark record declares its decision threshold before evaluating the
  candidate.
- An index or acceleration relation must improve the selected workload beyond
  noise after including build and storage cost. Otherwise retain the simpler
  publication.

## Diagnostic Compatibility Decision

The implementation may change private annotations, adapters, helper ownership,
and test seams. It may not weaken the repository's strict Pyright or Ruff
contract to deliver the optimization.

Existing precise suppressions are not automatically compatible forever. P0
classifies them; touched first-party suppressions are repaired in their owning
slice, external typing is concentrated at the adapter, and any retained
exception remains exact and testable.

The execution-integrity checker adds no public API or publication schema. A
checker or configuration change is a repository harness change and receives
focused negative-fixture verification plus independent review; it does not
require a package compatibility alias.

## Risks And Mitigations

| Risk | Mitigation |
| --- | --- |
| Polars IO plugin changes across the supported range | Isolate it in one adapter and run minimum/locked compatibility probes before resource migration. |
| Predicate root extraction or SQL pushdown changes semantics | Keep resource-owned domain filters, retain residual filtering, and test filter-plus-limit cases. |
| `is_pure=True` suppresses required execution | Require identity/replay tests and source-call counters before enabling it. |
| Selection cache races under `collect_all()` | Use a thread-safe once-only compact anchor and concurrency tests; never cache expanded relations. |
| Arrow typing work is hidden with `Any` or ignores | Use concrete protocols in the adapter, strict checking, runtime boundary tests, and diagnostic-integrity fixtures. |
| Static checker ossifies implementation or reports false positives | Restrict it to high-confidence AST rules; use behavior probes for materialization and pushdown. |
| DuckDB list aggregation exceeds its configured memory | Retain partitioned KEGG aggregation and measure process RSS, not only buffer-manager settings. |
| A direct Arrow load loses a necessary recovery/multi-pass boundary | Keep a justified Parquet spool when its lifecycle value is demonstrated and benchmarked. |
| Point-query optimization inflates publications | Rewrite queries first; gate ART or acceleration relations on build, RSS, size, and query evidence. |
| Benchmark improves by changing input or output | Freeze scope, record all runs and output contracts, and reject any mismatch before comparing cost. |
| CephFS cache variance changes a verdict | Use repeated local algorithmic runs and bounded CephFS operational observations with separate labels. |
| A checker change disables its own protection | Require negative fixtures and independent exact-head review for gate changes. |
| Completed plan history is rewritten | Keep predecessor plans immutable and record this work as a linked follow-up. |

## Rollback And Cleanup

- Private adapter and resource migrations are independently reversible before
  release when the predecessor public contract is preserved.
- A rejected resource candidate removes its temporary helper, suppression,
  test seam, and parallel path in the same slice.
- The existing generic Parquet publication path remains available only until a
  replacement strategy passes its relation and atomicity gates; it is then
  removed for that path rather than retained as a hidden fallback.
- UniProt idmapping selected behavior is an additive pre-v1 capability. Before
  release it may be reverted as one API/test/docs unit if the workload gate
  fails. After release, changing it requires an explicit compatibility record.
- No publication file is migrated in place. A schema or physical-index change
  builds a new staged publication, validates it, and requires separate formal
  replacement authority.
- Interrupted benchmark and publication stages are deleted after their failure
  evidence is captured; previous destinations remain unchanged.
