## Goal

Add the official zipped human Reactome GMT file as a separate gene-set
capability:

```text
ReactomePathways.gmt.zip
  └── ReactomePathways.gmt
```

The capability exposes pathway-to-gene-symbol membership and the official GMT
gene-set label without conflating symbols with UniProt, NCBI, ChEBI, or GtoP
identifier mappings.

This is the final planned v96 raw role. When all predecessor roles and this
role are supplied, a complete v0.5 publication has seventeen biological tables
corresponding to the seventeen official raw files, plus the five shared
metadata-v2 tables.

## Evidence And Source Semantics

The bounded v96 archive contains exactly one regular member named
`ReactomePathways.gmt`. Observed properties are:

| Observation | Value |
| --- | ---: |
| GMT pathway rows | 2,855 |
| Memberships | 140,638 |
| Unique `(pathway, gene_symbol)` pairs | 140,638 |
| Unique symbols | 11,963 |
| Duplicate symbols within a row | 0 |
| Empty symbols | 0 |
| Minimum fields per row | 3 |
| Maximum fields per row | 2,624 |
| GMT pathway IDs missing from human pathway metadata | 0 |

Each row is variable-width, tab-separated data:

```text
gene_set_name  reactome_pathway_id  gene_symbol...
```

The first field is a GMT gene-set label, not a byte-identical duplicate of
`ReactomePathways.txt` pathway names. Of the 2,855 v96 rows, 50 labels differ
from pathway metadata: 28 are explained by trailing whitespace in the pathway
metadata and 22 use a `_<stable ID>` suffix to disambiguate repeated labels.
There are no other observed mismatch classes.

Therefore the GMT label is preserved as `gene_set_name`; it is not normalized
to, overwritten by, or validated for equality with `pathway.pathway_name`.

Gene symbols are opaque official membership tokens. The file includes
non-HGNC-looking viral tokens such as `gag`, `gag-pol`, and `rev`. Bioextract
must not uppercase, resolve, or validate them against an external gene catalog.

## Accepted Decisions

| Concern | Decision |
| --- | --- |
| Capability boundary | GMT is a human gene-set relation, separate from the four-namespace mapping matrix. |
| Public method | Add `pathway_gene_sets()` returning one row per pathway/symbol membership. |
| Canonical columns | `reactome_pathway_id`, `gene_set_name`, `gene_symbol`. |
| Pathway name handling | Preserve GMT `gene_set_name`; do not force equality with pathway metadata. |
| Gene symbol handling | Trim structural TSV line endings only; preserve case, punctuation, and exact symbol text. |
| Species | File-scoped Homo sapiens behavior, matching the entity-pathway plan. |
| Archive | Support the official zip shape only; stream the one expected member without extracting into the repository. |
| Selection | Add no selected/grouped symbol API initially; native LazyFrame filters and joins are sufficient. |
| Storage | Publish one normalized `pathway_gene_set` table. |
| Publication | Add the role in profile v5/schema v0.5 after v0.4. |
| Release | Prefer one coordinated package/formal release for the final v0.5 capability set, separately authorized. |

## Scope

### In scope

- strict zip inventory and GMT parsing;
- one canonical membership row per pathway/symbol;
- preservation of official gene-set labels and symbols;
- factory role, whole-resource lazy relation, and human species behavior;
- optional pathway-ID cross-validation;
- v0.5 publication/reopen contract;
- complete-role v96 smoke, docs, and repository gate.

### Out of scope

- unzipped or caller-generated GMT variants;
- gene symbol synonym resolution, HGNC validation, UniProt conversion, or
  taxon inference;
- treating symbols as stable IDs;
- enrichment statistics, ranking, or pathway scoring;
- merging GMT membership into `pathway_genes()`;
- selected/grouped gene-set APIs, symbol indexes, or public query tuning;
- downloads, web services, package release, formal CephFS replacement,
  catalog activation, or old-artifact deletion.

## Construction And Source Contract

The file factory gains one keyword-only argument:

```python
ReactomeDatabase.from_files(
    ...,
    pathway_gene_sets=None,
    release_version=None,
)
```

`pathway_gene_sets` accepts the official zip archive path. A provided path must
be a regular file. The parser validates archive structure and content; the
basename is not release identity.

The archive contract is:

1. the zip central directory contains exactly one file entry;
2. its normalized member name is exactly `ReactomePathways.gmt`;
3. it is not encrypted, absolute, nested, or parent-traversing;
4. the member is streamed directly and decoded as UTF-8;
5. no repository or formal-resource extraction path is created; and
6. CRC/decompression errors fail the capability before publication.

The plan adds no public archive-size or row-limit option. Tests use compact
fixtures; real-snapshot work is bounded to the resolved v96 file and records
observed bytes in source provenance.

## Canonical Relation

The source role and physical table are both `pathway_gene_set`. The media type
recorded in `_bioextract.source_file` is `application/zip`.

Each GMT row with one or more symbols becomes:

```text
reactome_pathway_id
gene_set_name
gene_symbol
```

Canonicalization rules:

- require at least three fields;
- require non-empty gene-set name, Reactome pathway ID, and every symbol;
- preserve the gene-set name and symbols exactly after structural newline
  removal;
- explode symbols in source order, then deduplicate only exact canonical
  triples;
- sort published/query output by pathway ID, gene-set name, and symbol; and
- reject one pathway ID paired with multiple distinct GMT labels in the same
  source because that would make the normalized set identity ambiguous.

The table intentionally repeats `gene_set_name` on membership rows. This keeps
a GMT-only partial publication independently useful and preserves the official
first field without adding a second one-row-per-set table.

## Public Query Contract

```python
db.pathway_gene_sets() -> pl.LazyFrame
```

The method returns the canonical three-column lazy relation from either the
source archive or `pathway_gene_set` table. It scans no UniProt/NCBI/ChEBI/GtoP
mapping relation and does not call `pathway_genes()`.

Species behavior is:

```text
unscoped                         all GMT memberships
with_species("Homo sapiens")     all GMT memberships
with_species(any other value)    empty relation with stable schema
```

No per-row `species` column is added because human scope belongs to the
official source role. Callers needing a two-column TERM2GENE-style symbol
projection use native Polars:

```python
db.pathway_gene_sets().select("reactome_pathway_id", "gene_symbol")
```

No selected/grouped API is added in v0.5. A future reverse symbol lookup needs
a caller workload and a source/publication benchmark before it can justify a
new API or physical index.

## Cross-Source Validation

When the `pathway` role is present:

- validate that every GMT pathway ID exists in pathway metadata;
- require the referenced metadata species to be `Homo sapiens`;
- preserve any missing-ID memberships and emit one
  `missing_pathway_metadata` warning per distinct pathway ID; and
- do not compare `gene_set_name` for equality with `pathway_name`.

The 28 whitespace and 22 stable-ID-suffix label differences observed in v96
are valid independent source labels, not validation issues.

When pathway metadata is absent, ID validation is unavailable and the GMT-only
capability remains valid. No all-level hierarchy or reaction validation applies
to this source.

## Publication v0.5

After v0.4, publication identity becomes:

```text
bioextract.metadata_schema_version = 2
bioextract.source_schema_profile   = reactome-mapping-files-v5
bioextract.resource_schema_version = reactome-mapping-v0.5
```

All predecessor tables and their schemas remain unchanged. Supplying the GMT
role adds exactly `pathway_gene_set` with three ordered `VARCHAR` columns and
canonical table role.

Because the GMT source has no header row, this role adds no
`_bioextract.column_mapping` entries. The v0.4 Complex/EWAS mappings remain the
exact expected column-lineage set when those roles are present.

`from_duckdb()` validates:

- `application/zip` media type for the GMT source role;
- role-conditional table presence and exact schema;
- exact total table/view and column-lineage inventories;
- canonical role and non-negative recorded row count without biological
  recount;
- validation issue consistency; and
- existing pinned-file/read-only behavior.

The v0.5 reader rejects v0.4 and earlier publications. No compatibility view,
alias, dual write, or migration reader is added.

GMT framework.

## Implementation Task Graph

### G0 — Safe archive and GMT parser

Predecessor: accepted v0.4 entity implementation at an exact validated head.

## Compatibility, Release, And Rollback

The Python API is additive. Existing mapping, selection, Complex, and EWAS
methods remain unchanged. The publication reader intentionally moves to v0.5.

The preferred release boundary is one package containing the accepted v0.3,
v0.4, and v0.5 changes plus one separately authorized full v96 formal rebuild.
The release candidate must be built outside the formal path, verify all source
and reopened relations, record validation warnings, and be admitted and
atomically replaced under the publication release contract.

If candidate validation fails, remove only the identified v0.5 staging output
and keep the previously compatible package/formal artifact pair active. Do not
fall back by dropping GMT labels, silently accepting a malformed archive, or
adding an older-schema reader.

3. v0.5 publication/reopen and pathway-ID warnings;

## Risks And Controls

| Risk | Control |
| --- | --- |
| GMT labels overwrite pathway metadata names | Preserve `gene_set_name` as independent source data and never equality-normalize it. |
| Symbols are treated as stable gene IDs | Document opaque human symbol tokens and perform no external resolution. |
| Archive extraction escapes the task path | Stream exactly one validated member; create no extraction tree. |
| Variable-width rows are truncated | Require at least three fields and explicitly explode every membership. |
| Duplicate memberships distort enrichment | Exact canonical triple deduplication and v96 pair-count smoke. |
| GMT is merged with UniProt enrichment | Separate method/table/source role and no implicit union with `pathway_genes()`. |
| Package upgrade rejects the active older publication | Coordinate the final v0.5 package and formal artifact under separate release authority. |

## Completion Criteria

This slice is complete when:

- the official zip shape and variable-width GMT grammar fail closed;
- gene-set labels and symbols are preserved without false normalization;
- `pathway_gene_sets()` works from source and reopened publications with exact
  human scope;
- pathway metadata gaps remain visible without row loss or name rewriting;
- GMT-only and full seventeen-table v0.5 publications validate exactly;
- bounded v96 counts, mismatch classes, and semantic hashes are recorded;
- architecture, testing, signatures, examples, and implementation agree;
- the canonical repository gate passes; and
- handoff distinguishes implementation completion from any separately
  authorized package, formal publication, catalog, downstream, or cleanup
  action.
