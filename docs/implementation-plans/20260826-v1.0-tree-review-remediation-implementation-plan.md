## Goal

Close the honesty and identity defects in the public contract, then the
domain-correctness gaps, without adding resources, downloaders, or analysis
policy. Converge package identity on SCM-derived build metadata, separate
nightly evidence from formal package release, and make UniProt representation
normalization explicit at the caller-owned selection boundary.

This plan records delivery order. It is not runtime authority. The
[Domain Access Architecture](../architecture/20260729-v1.0-domain-access-architecture.md)
and [Materialized Dataset Contract](../architecture/tidy-dataset-contract.md)
remain authoritative until a later versioned successor updates them.

## Authority And Compatibility Baseline

- Repository guidance: `AGENTS.md`.
- Documentation map: `docs/README.md`.
- Test policy: `docs/testing/README.md`.
- Delivery: `docs/runbooks/repository-delivery.md`.

The tree review is observational. It does not enter the architecture authority
map as a current contract.

A successor that changes public API, publication schema, or README examples
must update the owning contract and tests together. Formal CephFS replacement
and formal package publication remain separately authorized release actions.

The accepted identifier decision is not an optional cleaning mode. A public
boundary either declares UniProt pipe-form input and normalizes it as part of
that input contract, or it does not apply the UniProt grammar. Official source
files continue to use their resource-owned parsers.

## Non-Goals

This plan does not authorize:

- publishing to CephFS or deleting a prior formal artifact;
- adding a resource, generic query facade, or enrichment statistic;
- a v1 metadata compatibility reader;
- depending on `biofetch`;
- publishing nightly builds to PyPI;
- running formal CephFS or full-real-snapshot work from a nightly job;
- treating Reactome v0.5 / `20260817-r1` remaining release gates as passed.

## Delivery Slices

The work is delivered as four independently reviewable slices. Each behavior
slice lands its owning contract, implementation, and focused tests together;
documentation must not claim a future behavior before that behavior lands.
The slices are ordered by dependency, but Slice 3 and Slice 4 may proceed
independently after their contract text is frozen.

   terminals (`compounds()`, `ancestors()`, `mappings()`, `scan_mapping()`,
   `unmatched_ids()`, …) are the taught API. Remove every `extract_*` and
   `read_mapping` example, not only the originally cited subset.
2. Correct the current metadata-v1 sentence in `go-kegg-tidy.md` and align its
   GO eager/lazy wording with the repository-wide ontology-closure exception.
3. Preserve the completed publication-inspection plan as an accurate
   historical v1 record. Label retained `dist/` and release-freeze records as

Validation: add a focused repository-owned check that compiles every Python
fence in both language READMEs and imports each changed public owner to resolve
the taught noun terminal. The owning resource suites execute those methods
against hermetic fixtures; README snippets that intentionally name external
official snapshot paths are not treated as executable fixtures. Then run
Markdown link and diff checks. This documentation-only slice does not require
CephFS or a full Python gate.

### Slice 2 — Package provenance and release harness

Reference basis: PDM backend
[SCM dynamic versions](https://backend.pdm-project.org/metadata/), the PyPA
[development-release model](https://packaging.python.org/en/latest/discussions/versioning/),
the PyPI [Trusted Publisher security model](https://docs.pypi.org/trusted-publishers/security-model/),
and GitHub [protected deployment environments](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/control-deployments).

1. Replace the static development placeholder and tag-time rewrite with the
   PDM backend's SCM-derived dynamic version. A clean untagged build must
   produce a canonical PEP 440 development identity tied to its source
   revision; a final release build must derive the exact canonical version
   from its release tag. A dirty source tree may still run editable development
   and tests, but it must fail before creating a wheel or sdist. It therefore
   cannot supply nightly, RC, final, or formal database-publication artifacts.
2. Split continuous evidence from formal release:
   - pull-request and main CI run the repository checks and build/install
     validation without publishing;
   - a scheduled nightly starts from a verified clean checkout of current main,
     builds its development wheel, runs `pdm run check`, checks the
     distributions, fresh-installs the wheel, runs a bounded installed-package
     smoke, and retains the artifacts for a named finite period;
   - nightly never uploads to PyPI and never enters CephFS or formal
     real-snapshot work;
   - an `rcN` is published only when external pre-release testing is explicitly
     authorized; and
   - final PyPI publication is triggered by publishing a GitHub Release for an
     already verified tag, through a dedicated Trusted Publishing workflow and
     protected `pypi` environment. A tag push alone does not publish.
3. Close every alternate publication trigger. The final job accepts only a
   `release.published` event whose release is not a prerelease **and** whose tag
   is the canonical PEP 440 final form `X.Y.Z`: three non-negative integer
   release segments, no `v` prefix, and no pre/dev/post/local component. The
   separate RC job requires both an explicitly published GitHub prerelease and
   the canonical tag form `X.Y.ZrcN`, where `N` is a positive integer; alpha,
   beta, dev, post, local, non-canonical, and UI-misclassified versions fail
   closed. Both upload jobs explicitly check out
   `github.event.release.tag_name`, resolve that tag to the expected commit,
   reject a dirty or mismatched tree, parse and canonicalize the tag before
   build, assert that its release kind matches the selected job, and assert
   that the built distribution identity exactly equals the canonical event tag.
   A tag-push workflow and `workflow_dispatch` may build and validate only:
   neither has an upload job, `id-token: write`, nor another PyPI credential
   path. Audit every workflow so no second PyPI upload path remains.
4. Remove or retire `scripts/sync_release_version.py` after the SCM build path
   and release workflow prove it redundant. Verify release tag, checked-out
   commit, distribution version, and uploaded artifact identity before the
   external write.
5. Amend the Materialized Dataset Contract so a new publication requires a
   resolvable package version. Resolve it before creating a staging database or
   mutating the destination; apply the same fail-closed rule to the shared and
   Rhea writers.
6. Preserve reader compatibility for existing metadata-v2 files whose literal
   package version is `"unknown"`. `inspect_publication()` may continue to
   surface that literal value. The literal is the observable unresolved
   sentinel: it never equals a canonical PEP 440 identity, cannot satisfy a
   package/publication compatibility check, and fails formal delivery
   preflight. Do not add a second status field or bump the metadata schema
   solely for this migration.
7. Require every formal publication candidate to run from a fresh installation
   of the exact built wheel. Editable installations remain valid for tests and
   temporary development artifacts but cannot establish formal publication
   provenance. Read the canonical version from installed wheel metadata, write
   a temporary DuckDB, reopen it through the public reader/inspection path, and
   assert exact equality with `bioextract.package_version`. Formal handoff then
   verifies the complete tag-to-commit-to-wheel-to-publication chain.

Repository changes cannot configure GitHub environment reviewers or the PyPI
Trusted Publisher by themselves. The delivery handoff must name those
control-plane steps and require authoritative readback; this plan does not
authorize a PyPI upload.

Validation: clean SCM final/RC/untagged cases; assert that a dirty source tree
creates neither wheel nor sdist; distribution metadata; `twine check`; fresh-
install import and bounded write/read smoke; fail-before-mutation tests for both
writers; legacy `"unknown"` read/inspection tests; an exact wheel-metadata-to-
DuckDB-metadata equality assertion; workflow syntax and event/ref/release-kind
guards. Include negative cases for an `X.Y.ZrcN` release misclassified as final
in the GitHub UI and for alpha, beta, dev, post, local, non-canonical, or final
tags misclassified as RC. An RC event tag whose checkout ref, resolved commit,
or built distribution identity differs must also fail closed. Prove that tag-
push/manual jobs cannot upload. The actual protected-environment and Trusted
Publisher configuration remains an externally verified release precondition.

### Slice 3 — Cross-resource UniProt input contract

The normalization target is caller-supplied selection input, not official
database source rows. It is mandatory at the declared boundary and has no
public `normalize` switch.

1. Accept either a non-empty trimmed plain accession without `|`, or one
   complete `sp|accession|entry_name` / `tr|accession|entry_name` value. All
   pipe-form fields are non-empty and the complete input must match. Every
   other pipe-bearing caller value raises `ValueError`; it does not become an
   unmatched identifier. Non-pipe values retain the current lookup/unmatched
   behavior; this slice does not introduce a new UniProt accession regex.
2. Add one private UniProt representation normalizer. Its output accession is
   the public `input_id` used for lookup, deduplication, grouped membership, and
   unmatched accounting. Do not add `raw_input_id` in this slice.
3. Amend the owning resource contracts before or with their implementation.
   Rhea must distinguish same-namespace representation normalization from
   prohibited cross-namespace identifier conversion.
4. Apply this exact capability matrix:

   | Public boundary | Target behavior |
   | --- | --- |
   | UniProtKB `namespace="uniprot"`, single/grouped | UniProt pipe or plain accession |
   | UniProt idmapping `namespace="uniprot"`, single only | UniProt pipe or plain accession; do not add grouped selection |
   | UniProtKB `entry_name`, `gene_name`, `gene_id`, `refseq`, `ensembl`, `isoform_id` | trim-only/existing namespace rule |
   | Reactome `namespace="uniprot"` | UniProt pipe or plain accession |
   | Rhea `namespace="uniprot"` | UniProt pipe or plain accession |
   | InterPro selection | UniProt pipe or plain accession |
   | OmniPath `namespace="protein"` | UniProt pipe or plain accession |
   | STRING `namespace="alias"` | strict UniProt pipe or existing non-pipe alias text |
   | STRING `namespace="string"` | trim-only exact STRING protein ID |
   | eggNOG and WikiPathways | trim-only exact owning identifier |
   | KEGG `namespace="uniprot"` | UniProt pipe or plain accession |
   | KEGG `ncbi_gene` and `kegg_gene` | existing namespace rule; no UniProt parser |

5. Make generic input-frame builders trim, drop empty values, and deduplicate
   only. The owning caller performs namespace-aware normalization before frame
   construction. Remove Rhea's permissive two-field parser and the shared
   helper's arbitrary database token, empty entry name, prefix-only, and
   extra-field acceptance.
6. Keep Reactome `ncbi` exact after trimming. ChEBI, Rhea non-UniProt, GO, and
   KEGG non-UniProt canonicalization remain owned by their resource/namespace.
   Do not add a generic public normalization API.

Validation: strict grammar and rejection tests; normalized public `input_id`
assertions; source/reopened-publication parity for every publication-backed
boundary; single and grouped selections where the public API already supports
both; UniProt idmapping single-selection coverage without adding grouped
support; and negative controls for every exact-text row in the matrix,
including a rejected non-UniProt pipe-bearing STRING alias. Official-source
parser tests remain separate.

### Slice 4 — GO/KEGG integrity and local contract hygiene

1. Restrict GO directory candidates to explicitly supported OBO and archive
   suffixes; reject false positives such as `.obo.bak`.
2. Validate every hierarchical GO edge endpoint before graph derivation.
   Source-backed malformed OBO raises a contextual `ValueError` naming the
   missing term/parent; invalid reopened publications continue to raise
   `IntegrityError`.
3. Pin KEGG publication paths and filesystem identity across validation and
   every later query/connect boundary for BRITE, organism mapping, and
   metabolic publication profiles.
4. Do not add a repository-wide runtime traversal cap. Accepted release
   layouts, role/suffix traversal, and any named overridable depth/count/byte
   limit require a later resource-owned contract and a fixture showing the
   failure it prevents. The GO suffix defect does not wait on that work.
5. Document the intentional GO frame-to-publication table mapping; do not
   rename either side without a successor schema. Retain the bounded ontology-
   closure materialization exception.
6. Change STRING and OmniPath capability errors to say snapshot/source rather
   than publication.
7. Require `TidyDataset.resource_name`; remove the `build_id_prefix` identity
   fallback and update every internal constructor.

Validation: GO false-suffix and dangling-endpoint fixtures; KEGG replacement
tests for all three publication profiles; resource contract tests;
construction/type checks for every `TidyDataset`; and docstring examples. No
new real-snapshot smoke enters the default gate.

## Stop Rules

- Do not start a new resource adapter while the four remediation slices are
  open.
- Do not add a metadata-v1 reader to make the current README true; change the
  README.
- Do not reject an existing metadata-v2 file solely because its package value
  is `"unknown"`; surface it as unresolved and never use it as compatibility
  evidence.
- Do not publish nightly artifacts to PyPI or generate a formal publication
  from an editable installation.
- Do not rewrite Reactome NCBI identifiers; the current exact-text behavior is
  authoritative.
- Do not apply a UniProt pipe parser outside an owning API's explicitly
  documented UniProt-capable boundary.
- Do not add a public normalization toggle or a `raw_input_id` column in this
  remediation.

## Validation Gate

Each slice ends with the smallest owning checks listed above. After all four
slices converge, run `pdm run check` because the combined work crosses public
documentation, identifier behavior, publication lifecycle, build metadata,
repository harnesses, and shared construction seams. Build and fresh-install
the final candidate wheel as a separate artifact check.

No check in this plan constitutes a package release, GitHub/PyPI control-plane
change, formal snapshot build, CephFS replacement, catalog activation, or old-
artifact deletion. Those actions require their own authorization and readback.
