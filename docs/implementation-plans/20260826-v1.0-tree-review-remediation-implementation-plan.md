# bioextract Tree-Review Remediation Implementation Plan

Version: v1.1
Date: 2026-08-26
Status: active implementation plan; not runtime authority

Applies to:
[bioextract tree review](../architecture/20260826-v1.0-bioextract-tree-review.md)

Reviewed commit: `64a88027159b0267bd2db72aa8c43a9f9838f226`

## Goal

Close the honesty and identity defects in the public contract, then the
domain-correctness gaps, without adding resources, downloaders, or analysis
policy.

This plan records delivery order. It is not runtime authority. The
[Domain Access Architecture](../architecture/20260729-v1.0-domain-access-architecture.md)
and [Materialized Dataset Contract](../architecture/tidy-dataset-contract.md)
remain authoritative until a later versioned successor updates them.

## Authority And Compatibility Baseline

- Repository guidance: `AGENTS.md`.
- Documentation map: `docs/README.md`.
- Test policy: `docs/testing/README.md`.
- Delivery: `docs/runbooks/repository-delivery.md`.

The tree review is observational. It does not enter the architecture authority
map as a current contract.

A successor that changes public API, publication schema, or README examples
must update the owning contract and tests together. Formal CephFS replacement
and package-tag publication remain separately authorized release actions.

## Non-Goals

This plan does not authorize:

- publishing to CephFS or deleting a prior formal artifact;
- adding a resource, generic query facade, or enrichment statistic;
- a v1 metadata compatibility reader;
- depending on `biofetch`;
- treating Reactome v0.5 / `20260817-r1` remaining release gates as passed.

## Delivery Units

Units are serial. A unit may be split into multiple commits, but its owning
contract and focused tests land with the behavior they define.

### Unit 0 — Public contract truth

1. Rewrite `README.md` and `README.zh-CN.md` so metadata v2 and noun selection
   terminals (`compounds()`, `ancestors()`, `mappings()`, `scan_mapping()`,
   `unmatched_ids()`, …) are the taught API. Remove `extract_*` / `read_mapping`
   examples.
2. Establish one package-version authority for development and release builds.
   Reconcile `pyproject.toml` with the existing `0.7.0` release tag and record
   whether post-tag development uses the last released version or an explicit
   next-development version. Do not retain `0.1.0` as an unexplained placeholder.
   Label retained `dist/` and freeze records as historical artifacts rather
   than competing current versions.
3. Make missing package identity fail publication before mutation in both the
   shared writer and Rhea's specialized writer. If the owning metadata contract
   instead adopts an explicit unresolved state, version that contract first;
   do not store `"unknown"` as a release-like package value.
4. Correct the current metadata-v1 sentence in `go-kegg-tidy.md`. Preserve the
   completed publication-inspection plan as an accurate historical v1 record,
   with a historical label where navigation context is otherwise ambiguous.

Validation: contract API and publication tests, plus README examples that
import. Documentation-only slices do not require a CephFS smoke.

### Unit 1 — Namespace-aware identifier normalization

1. Add a private UniProt-specific normalizer whose contract is trim plus
   accession extraction from a valid UniProt pipe form. Do not infer namespace
   merely because an arbitrary string contains `|`.
2. Apply that normalizer at every declared `namespace="uniprot"` input
   boundary, including UniProt knowledgebase and idmapping selection. Reuse it
   from Reactome and Rhea rather than retaining duplicate pipe parsing.
3. Audit current callers of `normalize_input_id`; keep it only as a renamed
   UniProt helper or replace non-UniProt callers with exact trim behavior.
4. Record and test the normalization matrix: UniProt pipe form canonicalizes to
   accession; Reactome `ncbi` remains exact after trim; ChEBI, Rhea, and GO keep
   their owning grammar-specific canonicalization. Do not add an NCBI prefix
   rewrite or a generic public normalization API.

Validation: focused shared-helper tests plus source/publication parity tests for
UniProt, Reactome, and Rhea. Include counterexamples proving that a pipe-bearing
non-UniProt exact identifier is not silently rewritten.

### Unit 2 — Source and publication integrity

1. Restrict GO directory candidates to explicitly supported OBO and archive
   suffixes; reject false positives such as `.obo.bak`.
2. Validate that every hierarchical GO edge endpoint exists in `term` before
   graph derivation. Source-backed malformed input raises the documented source
   validation error; invalid reopened publications continue to use
   `IntegrityError`.
3. Pin KEGG publication paths and filesystem identity across validation and
   every later query/connect boundary, covering BRITE, organism mapping, and
   metabolic publication profiles.
4. Treat recursive directory discovery as a separate contract decision. For
   each GO, ChEBI, Rhea, and KEGG constructor, inventory accepted official
   layouts, narrow role and suffix traversal, and then decide whether a named,
   overridable depth/count/byte limit is necessary. Do not derive a runtime
   hard cap solely from the agent traversal rule.

Validation: GO false-suffix and dangling-endpoint fixtures; KEGG replacement
tests for every publication profile; resource-specific discovery fixtures only
after the accepted layout and limit contract is documented.

### Unit 3 — Contract hygiene

1. Document the intentional GO frame-to-publication table mapping as a
   first-class mapping; do not rename either side without a successor schema.
2. Change STRING and OmniPath capability errors to say snapshot/source rather
   than publication.
3. Require `TidyDataset.resource_name`; remove the `build_id_prefix` identity
   fallback and update every internal constructor.
4. Retain the documented GO ontology-closure materialization exception. Do not
   rewrite it without workload evidence that falsifies its bounded-use claim.

Validation: resource contract tests, construction/type checks for every
`TidyDataset`, and docstring examples. No new smoke test enters the default gate.

## Stop Rules

- Do not start a new resource adapter while Unit 0 is open.
- Do not add a metadata-v1 reader to make the current README true; change the
  README.
- Do not treat `"unknown"` package versions in existing DuckDB files as
  scientific identity.
- Do not rewrite Reactome NCBI identifiers; the current exact-text behavior is
  authoritative.
- Do not apply a UniProt pipe parser to an undeclared or exact-text namespace.

## Validation Gate

Each unit ends with the smallest owning tests. After Units 0-3 converge, run
`pdm run check` because the combined work crosses public documentation,
identifier behavior, publication lifecycle, and shared construction seams.
Formal snapshot delivery and package publication remain separately scoped
release actions.
