## Goal

Add the two official human Reactome entity-to-pathway relations without
misclassifying them as external identifier mappings:

```text
Complex_2_Pathway_human.txt
Ewas2Pathway_human.txt
```

Here EWAS means Reactome EntityWithAccessionedSequence, not a genome-wide
association study.

The new relations expose Reactome entity membership, the referenced pathway,
and the official top-level pathway. They remain independently usable when
pathway metadata or hierarchy files are absent and gain stronger cross-source
validation when those optional roles are present.

## Evidence And Grain

The v96 sources are headered three-column TSV files:

| Source | Rows | Unique entities | Unique pathways | Unique top-level pathways | Exact duplicate rows |
| --- | ---: | ---: | ---: | ---: | ---: |
| `Complex_2_Pathway_human.txt` | 28,387 | 16,505 | 1,999 | 29 | 0 |
| `Ewas2Pathway_human.txt` | 82,411 | 33,628 | 2,333 | 29 | 0 |

Their official headers are:

```text
complex  pathway  top_level_pathway
ewas     pathway  top_level_pathway
```

Every observed pathway and top-level pathway exists in the human pathway
metadata. Every observed `top_level_pathway` is a reflexive ancestor of its
`pathway` through `ReactomePathwaysRelation.txt`.

Entity prefixes are not species authority. For example, an EWAS identifier may
begin with `R-BAN-` while its pathway and top-level pathway are `R-HSA-*`.
Human scope comes from the official `_human` file contract and referenced
pathways, not from the entity identifier prefix.

## Accepted Decisions

| Concern | Decision |
| --- | --- |
| Domain ownership | Treat Complex and EWAS as Reactome entity membership, separate from the external namespace mapping matrix. |
| Public relations | Add `complex_pathways()` and `ewas_pathways()` native lazy relations. |
| Initial selection API | Add none. Native Polars filtering is sufficient until a selected-ID workload justifies another public selection surface. |
| Species | Files are explicitly human. Unscoped and `with_species("Homo sapiens")` calls return the rows; another species returns an empty stable-schema relation. |
| Storage | Publish separate `complex_pathway` and `ewas_pathway` tables. |
| Source headers | Preserve official header lineage through exact metadata-v2 column mappings while exposing repository-standard semantic columns. |
| Endpoint gaps | Preserve source rows and emit warnings when optional pathway metadata lacks a referenced endpoint. |
| Top-level semantics | When hierarchy is supplied, a non-ancestor top-level claim is fatal; never silently recompute or replace the official value. |
| Publication | Add the roles in v0.4/profile v4 after v0.3. |
| Release | Implementation and temporary publication validation do not authorize package or formal resource replacement. |

## Scope

### In scope

- exact headered TSV parsing for both files;
- constructor roles and partial-source capability detection;
- public whole-resource lazy relations;
- exact human species behavior;
- metadata/pathway/hierarchy cross-validation;
- v0.4 publication and bounded reopen validation;
- source/publication parity, v96 smoke, docs, and repository gate.

### Out of scope

- parsing Complex or EWAS internal composition;
- mapping entity IDs to UniProt, genes, chemicals, or reaction participants;
- inferring an entity species from its stable-ID prefix;
- entity-name metadata not present in these files;
- selected/grouped entity APIs, reverse pathway indexes, or query limits;
- GMT gene symbols, enrichment statistics, web-service calls, or downloads;
- package release, formal CephFS replacement, catalog activation, or cleanup.

## Source And Table Contract

The factory gains two explicit keyword-only arguments:

```python
ReactomeDatabase.from_files(
    ...,
    complex_pathways=None,
    ewas_pathways=None,
    release_version=None,
)
```

Each argument is independently optional. A provided path must be a regular
file and must satisfy its exact header/schema. The filename is not used as
release identity.

The canonical relations are:

| Factory argument | Source role/table | Public method | Columns |
| --- | --- | --- | --- |
| `complex_pathways` | `complex_pathway` | `complex_pathways()` | `reactome_complex_id`, `reactome_pathway_id`, `top_level_reactome_pathway_id` |
| `ewas_pathways` | `ewas_pathway` | `ewas_pathways()` | `reactome_ewas_id`, `reactome_pathway_id`, `top_level_reactome_pathway_id` |

All columns are strings. Rows are deduplicated only by the exact canonical
triple. Multiple pathways or top-level contexts for one entity remain distinct
source observations.

## Header And Column Lineage

The parser requires the official ordered headers exactly. It then applies these
semantic renames:

| Table | Source header | Output column |
| --- | --- | --- |
| `complex_pathway` | `complex` | `reactome_complex_id` |
| `complex_pathway` | `pathway` | `reactome_pathway_id` |
| `complex_pathway` | `top_level_pathway` | `top_level_reactome_pathway_id` |
| `ewas_pathway` | `ewas` | `reactome_ewas_id` |
| `ewas_pathway` | `pathway` | `reactome_pathway_id` |
| `ewas_pathway` | `top_level_pathway` | `top_level_reactome_pathway_id` |

The publisher records exactly these six entries in
`_bioextract.column_mapping` when both roles are present, or the role-local
subset for a partial publication. The reason string is one repository-owned
constant meaning “Reactome semantic identifier name”; callers do not depend on
the prose value.

Missing, reordered, duplicated, or additional source headers fail closed.
Values are literal TSV strings with quoting disabled. Empty required fields and
ragged rows are invalid.

## Public Query Contract

```python
db.complex_pathways() -> pl.LazyFrame
db.ewas_pathways() -> pl.LazyFrame
```

Both methods:

- return the canonical three-column schema in the order above;
- scan only their owning file or publication table;
- return unique rows in deterministic entity/pathway/top-level order;
- raise at the capability boundary when the role is unavailable; and
- share source/reopened behavior.

Species behavior is explicit:

```text
unscoped                         all source rows
with_species("Homo sapiens")     all source rows
with_species(any other value)    empty relation with stable schema
```

No `species` column is added because the source is a file-scoped human
relation, not a per-row multispecies mapping. The file role and source
provenance retain that scope.

The initial slice adds no `select_complexes()`, `select_ewas()`, or new
`select_ids()` namespace. Native LazyFrame `.filter()`/`.join()` already gives
bounded exact selection without expanding the behaviorally public selection
contract. A future selected API requires a recorded caller workload and
source/publication performance evidence.

## Cross-Source Validation

Validation applies only when the supporting role exists.

### Pathway metadata present

For each entity relation:

- validate both `reactome_pathway_id` and
  `top_level_reactome_pathway_id` against the supplied `pathway` role;
- require referenced metadata rows to be `Homo sapiens`;
- preserve unmatched source rows; and
- emit one warning per distinct `(entity_role, endpoint_role, pathway_id)`.

Endpoint absence is non-fatal because source relations are authoritative
observations and the same upstream-release inconsistency policy already applies
to mapping rows.

### Pathway hierarchy present

When `pathway_relation` is supplied, require every declared top-level pathway
to be a reflexive ancestor of the row's pathway. A mismatch is fatal before
publication because it contradicts the source column's explicit semantic
claim. The publisher does not replace the official top-level value with a
computed ancestor.

When the hierarchy role is absent, reachability is an unavailable check, not a
warning. Cycles encountered while evaluating reachability are fatal source
integrity errors.

## Publication v0.4

After the v0.3 mapping predecessor, identity becomes:

```text
bioextract.metadata_schema_version = 2
bioextract.source_schema_profile   = reactome-mapping-files-v4
bioextract.resource_schema_version = reactome-mapping-v0.4
```

All v0.3 tables remain unchanged. Each entity source role adds exactly its
same-named table. Source media type remains `text/tab-separated-values`.

`from_duckdb()` validates:

- role-conditional table presence and exact three-column schema;
- role-conditional expected column-mapping entries and no extras;
- canonical table role and non-negative recorded row count;
- valid warning metadata and source media type;
- exact overall table/view inventory; and
- existing pinned-file identity and read-only connection behavior.

The v0.4 reader rejects v0.3 and earlier publications. No compatibility view,
alias, dual write, or automatic migration is added.

## Compatibility, Release, And Rollback

The Python additions are additive. Existing mapping methods, selection outputs,
and defaults remain unchanged. The publication schema is intentionally
incompatible and should normally continue to the v0.5 GMT plan before one
package/formal release.

If implementation stops at v0.4, package and matching formal publication need
a separate coordinated release task. Until then, retain package 0.6.0/current
formal v0.2 or the separately released v0.3 pair as the active compatible set.

On candidate failure, remove only the identified temporary/staging v0.4
artifact. Do not mutate the active formal publication, fabricate missing
entity rows, or add a compatibility reader as rollback.

## Risks And Controls

| Risk | Control |
| --- | --- |
| EWAS is confused with association-study data | Expand EntityWithAccessionedSequence in public docs and keep the method under Reactome. |
| Entity prefix is treated as species | Scope from the official human file and pathway IDs; include non-HSA entity fixtures. |
| Header renames lose provenance | Require exact headers and record exact metadata-v2 column mappings. |
| Metadata joins drop source rows | Validate separately, preserve rows, and emit endpoint warnings. |
| Top-level values drift from hierarchy | Conditional fatal reflexive-ancestor validation. |
| New selection APIs are added speculatively | Use native LazyFrame filtering until a measured caller need exists. |
| Package and artifact versions diverge | Keep release separate and coordinate exact v0.4/v0.5 schema identity. |

## Completion Criteria

This slice is complete when:

- both official files have independent constructor/query/publication/reopen
  capabilities;
- public schemas and official-header lineage are exact;
- human scope never depends on the entity ID prefix;
- pathway endpoint gaps remain visible without row loss;
- declared top-level pathways pass conditional hierarchy validation;
- all partial and combined source/publication parity tests pass;
- bounded v96 evidence records the observed counts and semantic hashes;
- architecture, testing, signatures, examples, and implementation agree;
- the full repository gate passes; and
- handoff distinguishes local implementation from any separately authorized
  package or formal publication release.
