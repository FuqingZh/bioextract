# Reactome Remaining Mapping Matrix Expansion Implementation Plan

Version: v1.0
Date: 2026-08-18
Status: complete — v0.3 contract, v96 smoke, canonical gate, package 0.7.0,
formal v0.5 publication, and catalog readback complete
Predecessor:
[Reactome Mapping Capability Expansion Plan](20260817-v1.0-reactome-mapping-capability-expansion-implementation-plan.md)
Target: `reactome-mapping-files-v3` and `reactome-mapping-v0.3`; package and
formal publication release separately authorized

## Goal

Extend the implemented UniProt pathway-level Reactome contract to the ten
remaining files in the official four-namespace mapping matrix:

- UniProt reaction mappings;
- NCBI pathway lowest/all-level and reaction mappings;
- ChEBI pathway lowest/all-level and reaction mappings; and
- GtoP pathway lowest/all-level and reaction mappings.

The result remains one `ReactomeDatabase` with explicit biological dimensions,
native replayable Polars relations, partial-source construction, exact
capability-aware DuckDB publication, and no network dependency.

This plan does not implement Complex/EWAS membership or Reactome GMT gene sets.
Those are independent child plans because their source grammars, biological
grains, and public relations differ from the six-column mapping family.

## Current Baseline

The released P1 contract in `bioextract==0.6.0` supports:

```text
namespace      uniprot
target         pathway
pathway_level  lowest_level | all_levels
```

It publishes `uniprot_pathway_lowest_level`,
`uniprot_pathway_all_level`, `pathway`, and `pathway_relation` under
`reactome-mapping-v0.2`. Existing defaults are UniProt, pathway, and
lowest-level.

This plan preserves those defaults and physical tables. It expands the private
role registry and adds tables; it does not replace the P1 roles with one union
relation.

## Source Evidence And Namespace Correction

The bounded v96 inventory and cardinalities are recorded in the predecessor
plan. Across the twelve mapping files, the observed total is 4,401,905 rows.
Every file is a headerless literal six-field TSV relation, and reaction names
demonstrate why CSV quoting must remain disabled.

One predecessor assumption is corrected before implementation: the public
namespace is `ncbi`, not `ncbi_gene`.

The v96 `NCBI2Reactome*` files contain mostly decimal Gene IDs but also official
NCBI/GenBank/RefSeq-style accessions:

| File | Decimal rows | Non-decimal rows | Unique non-decimal IDs | Examples |
| --- | ---: | ---: | ---: | --- |
| `NCBI2Reactome.txt` | 265,911 | 66 | 18 | `K02485`, `NM_000077.4`, `NC_012920` |
| `NCBI2Reactome_All_Levels.txt` | 779,859 | 183 | 18 | `NR_006880`, `U13369`, `X58075` |
| `NCBI2ReactomeReactions.txt` | 611,542 | 300 | 34 | `AF516878`, `BAC53723`, `NP_001104590` |

Calling this `ncbi_gene` or enforcing decimal identifiers would reject
official rows and overstate their identifier semantics. Because the role has
not yet been implemented, the design is corrected without a compatibility
alias:

```text
public namespace  ncbi
source ID column  ncbi_id
```

## Accepted Decisions

| Concern | Decision |
| --- | --- |
| Public namespaces | `uniprot`, `ncbi`, `chebi`, and `gtop`. |
| Targets | `pathway` and `reaction` remain distinct. |
| Pathway levels | `lowest_level` and `all_levels`; reaction mappings have no pathway level. |
| Storage | One physical table per namespace/target/level role. No union table or nullable target columns. |
| Construction | Extend explicit keyword-only `from_files()`. Do not add directory discovery or a public role dictionary in this slice. |
| Whole-resource access | Extend `pathway_mappings()` and add `reaction_mappings()`. |
| Selection | Reuse `select_ids()`/`select_groups()` and configured `mappings()`/`unmatched_ids()` behavior. |
| Selected output | Keep source-specific identifier columns. Existing UniProt selected output remains byte-for-byte schema compatible. |
| UniProt enrichment | `pathway_genes()` remains the UniProt projection; no generic member facade is introduced. |
| Evidence grain | Deduplicate only exact six-column rows; preserve evidence-distinct rows. |
| Reaction meaning | Identifier-to-reaction-event evidence only. No participant role, direction, regulation, catalyst, or graph claim. |
| Publication | Bump to source profile v3 and resource schema v0.3; metadata remains v2. |
| Release | Prefer one later package/formal publication after all accepted remaining plans, but keep release independently authorized. |

## Scope

### In scope

- ten remaining official mapping-family inputs;
- strict shared role-aware parsing;
- whole-resource pathway and reaction relations;
- single and grouped exact-ID selection for all four namespaces;
- namespace-specific input normalization;
- generalized pathway closure and missing-metadata validation;
- exact partial and combined v0.3 publication/reopen behavior;
- source/publication parity, v96 smoke, docs, and repository validation.

### Out of scope

- Complex, EWAS, or GMT parsing;
- reaction participant topology or reaction metadata beyond mapping rows;
- ID conversion between namespaces;
- orthology, pathway enrichment statistics, or Reactome Analysis Service calls;
- a generic mapping dictionary, public role registry, or directory scanner;
- `pathway_genes()` for NCBI, ChEBI, or GtoP;
- public pagination, row limits, batch controls, cache controls, or index knobs;
- package publication, formal CephFS replacement, catalog activation, or old
  artifact deletion.

The complete v0.3 mapping matrix is:

| Namespace | Target | Level | Factory argument | Source role and table | Source ID column |
| --- | --- | --- | --- | --- | --- |

| `uniprot` | pathway | all | `uniprot_all_levels` | `uniprot_pathway_all_level` | `uniprot_id` |
| `uniprot` | reaction | — | `uniprot_reactions` | `uniprot_reaction` | `uniprot_id` |
| `ncbi` | pathway | lowest | `ncbi_mapping` | `ncbi_pathway_lowest_level` | `ncbi_id` |
| `ncbi` | pathway | all | `ncbi_all_levels` | `ncbi_pathway_all_level` | `ncbi_id` |
| `ncbi` | reaction | — | `ncbi_reactions` | `ncbi_reaction` | `ncbi_id` |
| `chebi` | pathway | lowest | `chebi_mapping` | `chebi_pathway_lowest_level` | `chebi_id` |
| `chebi` | pathway | all | `chebi_all_levels` | `chebi_pathway_all_level` | `chebi_id` |
| `chebi` | reaction | — | `chebi_reactions` | `chebi_reaction` | `chebi_id` |
| `gtop` | pathway | lowest | `gtop_mapping` | `gtop_pathway_lowest_level` | `gtop_id` |

| `gtop` | reaction | — | `gtop_reactions` | `gtop_reaction` | `gtop_id` |

Pathway table columns are:

```text
<namespace-specific source ID>
reactome_pathway_id
reactome_url
pathway_name
evidence_code
species
```

Reaction table columns are:

```text
<namespace-specific source ID>
reactome_reaction_id
reactome_url
reaction_name
evidence_code
species
```

All values are stored as strings. The source role/table name carries target and
level identity; those constants are not repeated on every row.

## Public Construction Contract

The final v0.3 file factory is:

```python
ReactomeDatabase.from_files(
    *,
    uniprot_mapping=None,
    uniprot_all_levels=None,
    uniprot_reactions=None,
    ncbi_mapping=None,
    ncbi_all_levels=None,
    ncbi_reactions=None,
    chebi_mapping=None,
    chebi_all_levels=None,
    chebi_reactions=None,
    gtop_mapping=None,
    gtop_all_levels=None,
    gtop_reactions=None,
    pathways=None,
    relations=None,
    release_version=None,
)
```

The long keyword-only signature is intentional. It keeps partial snapshots
explicit, type-checkable, and auditable without exposing a generic role map.
Callers supplying a conventional complete snapshot may construct the call in
their own resource configuration; bioextract does not infer release identity
or climb parent directories.

Rules:

1. at least one role is required;
2. every provided path must be a regular file;
3. the argument name is the authoritative role declaration;
4. a recognized official basename supplied to a different known role is
   rejected, but arbitrary renamed files are validated by content rather than
   by filename identity;
5. missing optional roles remain unavailable capabilities; and
6. `release_version` remains caller-declared and is never inferred.

## Public Query Contract

### Whole-resource relations

```python
db.pathway_mappings(
    *,
    namespace="uniprot",
    pathway_level="lowest_level",
) -> pl.LazyFrame

db.reaction_mappings(
    *,
    namespace="uniprot",
) -> pl.LazyFrame
```

`pathway_mappings()` accepts all four namespaces and preserves the existing
UniProt/lowest-level default. `reaction_mappings()` has no default biological
fallback beyond its explicit default namespace; absence of that role raises at
the capability boundary.

Each method returns the exact source-specific six-column schema defined above.
It scans only the selected source file or publication table. No call unions
namespaces, targets, or pathway levels.

`pathway_genes(pathway_level=...)` remains unchanged and UniProt-specific.
Callers needing an NCBI edge relation use
`pathway_mappings(namespace="ncbi", ...)` and an explicit Polars projection;
ChEBI and GtoP mappings are not genes.

### Selection dimensions

The selection factories become:

```python
db.select_ids(
    ids,
    *,
    namespace="uniprot",
    target="pathway",
    pathway_level=None,
)

db.select_groups(
    ids_by_group,
    *,
    namespace="uniprot",
    target="pathway",
    pathway_level=None,
)
```

Resolution is explicit:

- `target="pathway", pathway_level=None` resolves to `lowest_level` and
  preserves current behavior;
- `target="pathway"` also accepts an explicit `lowest_level` or `all_levels`;
- `target="reaction"` requires `pathway_level=None`; and
- any pathway level supplied with a reaction target raises `ValueError`.

Changing the inspectable default from the string `lowest_level` to `None` is a
documented pre-v1 signature change that removes an irrelevant reaction
parameter while preserving every existing omitted-argument result.

The selected `mappings()` schema is target- and namespace-specific:

```text
pathway:
input_id, <source ID>, reactome_pathway_id, pathway_name,
evidence_code, species, reactome_url

reaction:
input_id, <source ID>, reactome_reaction_id, reaction_name,
evidence_code, species, reactome_url
```

Grouped output prepends `group_id`. `unmatched_ids()` retains its current
single/grouped columns. The source-specific ID is not replaced with a generic
`source_id`; for existing UniProt pathway calls, the output columns and order
remain unchanged.

### Namespace normalization

Normalization is private, namespace-aware, and preserves caller lineage:

| Namespace | Accepted input | Lookup value | Output `input_id` |
| --- | --- | --- | --- |
| `uniprot` | accession or UniProt pipe form | accession | accession |
| `ncbi` | any non-empty exact official identifier after trimming | same text | same text |
| `chebi` | decimal ID or case-insensitive `CHEBI:<digits>` | canonical decimal text without prefix | `CHEBI:<integer>` |
| `gtop` | decimal ID after trimming | same decimal text | same decimal text |

NCBI inputs are deliberately not restricted to digits and are not rewritten
from `ncbi-geneid:` prefixes. ChEBI normalization mirrors the canonical
namespace form at the public input boundary while joining the official numeric
source column. GtoP IDs remain official numeric strings; no unverified prefix
syntax is invented.

Empty inputs are dropped as today. A non-empty identifier that violates the
declared ChEBI or GtoP grammar raises `ValueError`; it is not reported as merely
unmatched.

## Parsing And Validation

One private role registry supplies filename, table, source column, target
column, event-name column, and schema to the existing strict mapping-family
parser.

Every mapping role must:

- parse literal TSV with quoting disabled;
- require exactly six non-empty fields;
- retain literal event names, including quotes and trailing source text;
- deduplicate only exact six-column rows;
- preserve evidence-distinct rows;
- require a non-empty source identifier and a Reactome stable event ID;
- preserve the source identifier text without cross-namespace conversion; and
- use Polars expressions rather than Python row materialization for bulk
  canonicalization.

Pathway validation generalizes P1:

- if `pathway` is present, retain missing-metadata mappings and emit one
  `missing_pathway_metadata` warning per distinct `(role, pathway_id)`;
- if a namespace's lowest-level, all-level, and `pathway_relation` roles are
  present, require exact reflexive-closure parity at
  `(source_id, pathway_id, evidence_code, species)` grain; and
- missing comparison roles mean the check is unavailable, never that an
  all-level capability may be synthesized.

Reaction roles have no pathway metadata or hierarchy validation. Their
`reactome_reaction_id` remains an opaque stable event identifier. Mapping files
do not establish reaction inputs, outputs, catalysts, regulation, or direction.

## Publication v0.3

Publication identity becomes:

```text
bioextract.metadata_schema_version = 2
bioextract.source_schema_profile   = reactome-mapping-files-v3
bioextract.resource_schema_version = reactome-mapping-v0.3
```

The four P1 biological tables remain unchanged. Each newly supplied mapping
role adds exactly its same-named table. `_bioextract.source_file` is the sole
capability inventory; there is no capability side table.

`from_duckdb()` must validate:

- unique allowed source roles and the TSV media type;
- exact source-role-to-table presence;
- no extra tables or views;
- exact ordered physical column schemas and canonical table roles;
- non-negative recorded row counts without recounting biological tables;
- metadata-v2 validation issue consistency; and
- pinned-file identity before and after validation.

The v0.3 reader intentionally rejects v0.2 publications. No compatibility
view, alias, dual write, or automatic migration is added. All P1 Python calls
retain their source behavior, but a package containing the v0.3 reader must not
be released to users of the formal v0.2 artifact without a coordinated formal
publication decision.

## Compatibility, Release, And Rollback

This is an additive biological API with one deliberate signature cleanup:
selection `pathway_level` defaults to `None` and resolves to the existing
lowest-level behavior for pathway targets. Existing UniProt output schemas and
defaults remain unchanged.

The publication schema is intentionally incompatible. Preferred delivery is:

1. merge and validate v0.3 code locally;
2. continue through the accepted v0.4/v0.5 child plans if they are being
   delivered in the same release train;
3. publish one package only after selecting the final schema version; and
4. build, validate, catalog, and atomically replace one matching formal
   Reactome artifact under separate release authority.

Intermediate v0.3 package/formal release is allowed only by an explicit release
task. If candidate validation fails, delete only the identified staging output
and keep package 0.6.0 plus the current formal v0.2 publication available. Do
not restore compatibility through an undocumented v0.2 reader.

## Intended Review Splits

1. role registry, parser fixtures, and NCBI naming correction;
2. NCBI pathway public/query/publication slice;
3. UniProt reaction plus ChEBI slice;
4. GtoP slice;
5. v0.3 convergence, docs, smoke evidence, and full gate.

Each review must contain source and reopened behavior for the capability it

## Risks And Controls

| Risk | Control |
| --- | --- |
| NCBI data is falsely constrained to Gene IDs | Use `ncbi`/`ncbi_id`, preserve exact source text, and test non-decimal v96 examples. |
| Reaction mappings are mistaken for reaction topology | Use a separate target/method/table and state the evidence-only boundary in API docs. |
| One namespace leaks into another | Namespace-aware normalization, explicit roles, and wrong-prefix tests. |
| New files create a giant scan | Resolve one role before scan/query; never union by default. |
| Evidence rows collapse | Deduplicate exact full rows only; test differing evidence codes. |
| Package upgrade strands the current formal artifact | Keep package/formal release separate and coordinate the exact schema version. |
| Full v96 validation is slow or memory-heavy | Use fixed role-local scans, bounded concurrency, semantic hashes, and measured evidence before optimization. |

## Completion Criteria

The mapping-matrix slice is complete when:

- all twelve official mapping roles have explicit construction, query,
  capability, source-role, table, and reopen contracts;
- `ncbi` official mixed identifiers are preserved without a false Gene-only
  promise;
- pathway and reaction schemas remain distinct;
- all four namespace normalizers and selection outputs are tested;
- each role works alone and in a full v0.3 publication;
- generalized pathway closure and metadata-warning behavior pass on v96;
- source and reopened hashes agree for whole, species, selected, grouped, and
  unmatched relations;
- architecture, testing, README/docstrings, signatures, and implementation
  agree;
- the canonical repository gate passes; and
- the handoff explicitly states whether package and formal publication release
