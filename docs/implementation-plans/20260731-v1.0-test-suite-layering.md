# bioextract v1.0 Test Suite Layering Plan

Version: v1.0
Date: 2026-07-31
Status: completed

## Goal

Replace the flat, mixed-responsibility `tests/` layout with explicit unit,
contract, integration, and external-snapshot smoke boundaries. The migration
must improve focused feedback and ownership without changing public APIs,
publication schemas, generated files, or domain behavior.

The pre-migration baseline is:

- 18 flat test modules;
- 7,619 lines of test code;
- 225 test functions and 482 collected pytest cases; and
- one canonical `pdm run check` gate covering the complete hermetic suite.

## Preserved Contracts

- All existing assertions and parametrized cases remain covered.
- The first structural migration does not reduce the 482-case collection
  baseline.
- `pdm run check` continues to cover every hermetic unit, contract, and
  integration test.
- CephFS and other host-owned snapshots remain read-only and outside the
  default pytest run.
- Tests continue to use compact local fixtures and never download source
  releases.
- No source package, public import, DuckDB/Parquet schema, provenance record,
  or documented domain behavior changes as part of this migration.

## Target Layout

```text
tests/
  unit/
    <resource>/
  contract/
    api/
    publication/
    resources/<resource>/
  integration/
    <resource>/
  smoke/
    publications/
  fixtures/
    <resource>/
  _support/
```

The directory is the authoritative test category. Pytest markers describe
orthogonal runtime requirements only; they do not duplicate the directory
taxonomy.

## Execution Slices

### Slice 1: Structure And Shared Contracts

Move pure grouped-input tests to `unit/shared`, public import and behavior
documentation gates to `contract/api`, and shared publication invariants to
`contract/publication`.

Acceptance:

- old flat files are removed;
- the moved tests collect the same number of cases;
- focused unit and contract runs pass; and
- no source or publication behavior changes.

### Slice 2: Multi-Relation DuckDB Resources

Split ChEBI, Rhea, KEGG metabolic, and UniProt by responsibility:

- pure parser, normalization, and algorithm tests under `unit`;
- metadata, schema, capability, security, atomicity, and reader rejection
  tests under `contract`; and
- compact official-format build, reopen, select, and extract paths under
  `integration`.

Acceptance:

- every original case remains represented;
- mixed pure-algorithm/publication tests are separated when one failure would
  otherwise obscure the owning boundary; and
- focused tests pass for each resource.

### Slice 3: Remaining Resources

Migrate GO, KEGG BRITE and mapping, eggNOG, InterPro/Pfam, Reactome,
WikiPathways, STRING, and OmniPath. Rename local-fixture tests currently named
`smoke` to minimal round-trip or integration names.

Keep resource-specific fixtures local. Add shared support only for genuinely
identical archive or text/gzip construction; do not create a global domain
fixture abstraction.

Acceptance:

- no flat `tests/test_*.py` files remain;
- layer names match actual dependency boundaries; and
- per-resource focused commands remain discoverable.

### Slice 4: Harness And Documentation

Add repository-owned focused commands for unit, contract, integration, and
explicit smoke runs. Keep the complete hermetic suite behind `pdm run test`
and `pdm run check`. Update CI only after the same local command surface is
stable.

Update `docs/testing/README.md`, the documentation authority map, and
resource-specific focused commands to use the layered paths.

Acceptance:

- pytest strict configuration and marker registration reject taxonomy drift;
- default collection excludes external snapshot smoke;
- unit, contract, integration, and full gates all pass; and
- searches find no current documentation pointing to removed flat paths.

## Fixture Boundary

- A root `conftest.py`, if needed, contains only repository-wide pytest
  controls.
- Resource fixtures live beside their owning tests.
- Stable official-format samples may live under `tests/fixtures/<resource>/`.
- Dynamic malformed inputs remain fixture factories close to their tests.
- `tests/_support/` is limited to format-neutral mechanics such as safe archive
  or plain/gzip test-file creation.

## Verification

Run, in dependency order:

```console
pdm run test-unit
pdm run test-contract
pdm run test-integration
pdm run test
pdm run check
```

Collection must be at least the 482-case pre-migration baseline. Any increase
must be explained by splitting a previously mixed case; a decrease is a
blocking regression.

External publication smoke is a separate, explicitly invoked read-only gate
and is not required for this structure-only migration.

## Intended Review Batches

1. shared/API/publication structure and testing contract;
2. ChEBI, Rhea, UniProt, and KEGG metabolic separation;
3. remaining resource separation and fixture locality;
4. pytest/PDM/CI path convergence and final documentation cleanup.

Each batch preserves behavior independently and can be reviewed by ownership
boundary rather than as one mechanical directory move.

## Closeout

The layering migration landed in PR #11 (`ec7ccbf`). At that closeout point,
the hermetic suite contained 485 collected cases:

- 11 unit cases;
- 284 contract cases; and
- 190 integration cases.

The three-case increase over the 482-case baseline is intentional:

- one repository-wide analytical-engine thread-limit guard;
- one KEGG module-placeholder parser case split from its publication
  round-trip; and
- one UniProt molecular-weight algorithm case split from its publication
  acceptance path.

The current hermetic gate contains 598 collected cases: 15 unit, 376 contract,
and 207 integration cases. This later growth does not change the verified
482-to-485 migration accounting above. The external-snapshot suite remains
opt-in and skips when `BIOEXTRACT_SMOKE_DUCKDBS` is unset.

CI continues to call the single canonical `pdm run check` gate. Test-layer
commands bound Polars and DuckDB worker counts; no pytest process-level
parallelism or layer-level CI fan-out was added.
