# bioextract v1.0 Runtime And Constructor Convergence Plan

Version: v1.0
Date: 2026-08-05
Status: accepted
Authority: [Domain Access Architecture](../architecture/20260729-v1.0-domain-access-architecture.md), [Materialized Dataset Contract](../architecture/tidy-dataset-contract.md), and [Repository Test Standard](../testing/README.md)
Historical basis: [Archived Constructor Source Convergence Plan](../archive/20260731-v1.0-constructor-source-convergence.md)

## Goal

Close the remaining pre-v1.0 runtime-validation and constructor-source gaps in
one dependency-aware program:

1. make repository-owned validation use a measurable native-thread budget;
2. distinguish that library budget from host-wide task admission and OS process
   containment;
3. merge release discovery into the existing heterogeneous file-profile
   constructors for Rhea and KEGG metabolic;
4. remove ChEBI's ambiguous generic release constructor while preserving its
   two genuinely different representations; and
5. remove superseded public entrypoints without compatibility aliases.

The runtime slice lands first so every later public-contract slice can run its
complete gate on a constrained shared host. The constructor slices remain
independently reviewable and do not share a generic cross-resource resolver.

## Accepted Decisions

- The public base-input parameter is named `source`. `release_version` names
  release identity; `release` and `release_source` are not public path
  parameters. Resource-local implementation variables may use
  `release_source` or `base_source`.
- `source` discovers the roles not replaced by explicit keyword arguments.
  One explicit argument replaces its whole logical role; it never appends to
  a discovered role.
- Rhea removes `from_release()` and folds discovery into `from_files()`.
- KEGG metabolic removes `from_metabolic_release()` and folds discovery into
  `from_metabolic_files()`.
- ChEBI removes `from_release()` but keeps representation-specific
  `from_obo()` and `from_table_files()` entrypoints.
- `BIOEXTRACT_TEST_THREADS` remains the single repository validation-budget
  knob. Its name is retained to avoid another configuration migration even
  though the complete `pdm run check` pipeline consumes it.
- The repository budget constrains known native worker pools. It is not a
  promise that process NLWP equals the configured value.
- Host-wide heavy-task admission and per-worker process-tree containment belong
  to AO or another host control plane, not to bioextract.

### Baseline measurement (2026-08-05)

The first measurement used the isolated implementation worktree, the existing
locked dependency set, and a process-tree monitor. All stages passed. Peak
values are the sum of `NLWP` and RSS across the command's process tree, not a
claim about one worker process:

| Stage | Peak NLWP | Peak RSS | Elapsed |
| --- | ---: | ---: | ---: |
| `lock-check` | 2 | 61 MiB | 1.6 s |
| `format-check` | 2 | 44 MiB | 1.1 s |
| `lint` | 194 | 50 MiB | 1.3 s |
| `typecheck` | 9 | 469 MiB | 13.7 s |
| `test` (602 passed) | 398 | 277 MiB | 259 s |

The high lint and test peaks are the concrete reason for the runtime slice;
they include native helper pools and are not solved by changing only the
DuckDB connection setting.

The baseline must be re-read at the start of each implementation slice. A
newer implementation or test result overrides this plan's implementation
assumptions but not its accepted public outcomes.

## Execution Update (2026-08-05)

The runtime slice and the three constructor migrations are implemented in the
isolated implementation worktree. The current focused constructor suite has
99 passing contract/integration tests, and the complete constrained gate now
passes 607 tests in 234.49 seconds with `BIOEXTRACT_TEST_THREADS=1`. The gate
also passes lock, format, lint, and strict type checks.

The public result is now:

- `RheaDatabase.from_files(source=None, *, ...)` discovers and overlays a
  complete release, with no `from_release` alias.
- `KEGGDatabase.from_metabolic_files(source=None, *, ...)` does the same for
  the metabolic profile, with no `from_metabolic_release` alias.
- `ChEBIDatabase.from_obo(source, ...)` and
  `ChEBIDatabase.from_table_files(source=None, ...)` make the representation
  choice explicit; the generic `from_release` alias is absent.

Directory and archive discovery share duplicate-candidate, safe-member, whole
role-replacement, physical-file, and final-provenance checks. The plan remains
open for PR delivery, exact-head review, and final current-document readback;
the host/AO admission and hard process-tree containment control remains an
external control-plane dependency.

## Boundaries And Invariants

Across every slice:

- source discovery and biological validation stay in the owning resource
  package under `src/bioextract/`;
- `from_duckdb()` and publication inspection remain separate, caller-supplied
  publication readers;
- no downloader, `biofetch`, downstream catalog, or application dependency is
  introduced;
- DuckDB biological relations, metadata schema v1, resource schema versions,
  selection APIs, and output columns remain unchanged;
- provenance contains the actual final inputs used after overlay resolution;
- filenames and directory names never establish release identity;
- archives retain traversal-safe inspection and deterministic member
  selection;
- tests use temporary local fixtures and ordinary code PRs perform no CephFS
  writes; and
- this is a pre-v1.0 breaking convergence: removed constructors have no alias,
  deprecation wrapper, or compatibility dispatch.

### Cross-cutting FASTA transport invariant

Every public role whose logical format is FASTA accepts both plain text and a
gzip-compressed stream. Compression is detected from content magic rather than
the basename, so gzip content does not require a `.gz` suffix and a suffix does
not establish the parser. Gzip is a transport wrapper around the same FASTA
role; it does not create a separate constructor, keyword, source profile,
schema, or release identity.

The parser streams the selected transport and records the caller's actual input
path and detected media type as provenance. Gzip headers and filenames never
supply release metadata. A zip, tar, or `tar.gz` bundle remains an archive and
is accepted only when the owning constructor explicitly supports archive
discovery; it is not treated implicitly as one compressed FASTA stream.

Current UniProt canonical and isoform FASTA inputs already satisfy this
contract, so this plan adds no separate FASTA implementation slice. Their
regression gate retains plain/gzip record and validation equivalence, gzip
content under a non-`.gz` basename, path-specific corrupt-stream failure, and
the same empty, duplicate-ID, header, and sequence validation after
decompression. Future FASTA roles adopt the same minimum transport contract in
their owning resource package.

## Track A: Repository And Host Runtime Limits

### Three distinct control layers

| Layer | Owner | Required outcome |
| --- | --- | --- |
| Native-library worker budget | bioextract | Known Polars, Rayon, DuckDB, BLAS, OpenMP, and NumExpr pools do not exceed `BIOEXTRACT_TEST_THREADS` during repository validation |
| Heavy validation admission | AO or host runner | Initially admit at most one full repository gate on the shared host at a time |
| Worker process-tree containment | AO or host service manager | Bound and observe all descendants with an OS-owned containment boundary |

Passing the repository-level test proves only the first row. Documentation and
closeout reports must not describe it as a hard cap on total processes or
threads. Current AO does not provide a per-worker systemd scope, so the final
two rows require a separate host-owned change before host-wide resource
enforcement may be called complete.

### Repository budget contract

`BIOEXTRACT_TEST_THREADS` is a positive integer ceiling with these operating
defaults:

| Context | Budget |
| --- | --- |
| normal local validation and CI | `4` |
| external-publication smoke | `2` |
| shared-host or AO full-gate closeout | `1` |

Before the child command imports native libraries, the repository-owned
validation launcher or equivalent PDM configuration propagates the ceiling to:

- `POLARS_MAX_THREADS`;
- `RAYON_NUM_THREADS`;
- `OMP_NUM_THREADS` and `OMP_THREAD_LIMIT`;
- `OPENBLAS_NUM_THREADS`;
- `MKL_NUM_THREADS`;
- `BLIS_NUM_THREADS`;
- `NUMEXPR_NUM_THREADS`;
- `NUMEXPR_MAX_THREADS`; and
- `VECLIB_MAXIMUM_THREADS`.

An unset native variable receives the common ceiling. A positive caller value
below the ceiling is preserved. A value above the ceiling is clamped; an
invalid value fails before validation starts. This prevents a host default such
as an uncapped OpenBLAS pool from bypassing the repository budget.

The budget applies to `lock-check`, format checking, Ruff, Pyright, and pytest
when they are invoked through repository-owned PDM gates. The implementation
must measure Pyright/Node behavior before deciding whether
`UV_THREADPOOL_SIZE` is relevant; it must not add that variable speculatively.
Real publication builds outside the validation commands retain their current
caller-controlled runtime behavior.

### Executable feedback

The runtime slice must:

1. move environment setup before DuckDB, Polars, NumPy, or another native
   analytical import;
2. retain direct-pytest fallback behavior in the root conftest;
3. retain DuckDB's connection-level `threads` configuration;
4. use an isolated subprocess to import representative analytical libraries,
   execute a small operation, and read back Polars, DuckDB, BLAS, and OpenMP
   pools;
5. add `threadpoolctl` to the test dependency group if it is not already
   available through a direct test dependency;
6. exercise both the default budget and `BIOEXTRACT_TEST_THREADS=1`; and
7. record peak process-tree NLWP and RSS for each stage of `pdm run check`
   without asserting that helper threads make total NLWP equal the worker-pool
   ceiling.

Until AO or the host runner has a real admission mechanism, all later full
gates in this plan run serially with `BIOEXTRACT_TEST_THREADS=1`. A shared-host
semaphore and a per-worker cgroup or equivalent containment mechanism are an
external follow-up, not a bioextract implementation detail. Its limits must be
chosen from the measured bounded peak plus explicit headroom rather than an
invented fixed `TasksMax` value.

## Track B: Common Source Overlay Contract

### Public vocabulary

The constructor name identifies the logical representation or heterogeneous
role profile. The parameter vocabulary is:

- `source`: optional base file, directory, or archive interpreted by the
  owning constructor;
- explicit role keywords: exact logical inputs that override source discovery;
  and
- `release_version`: caller-declared or content-validated release identity,
  never a filesystem path.

The common optional-source call matrix is:

| `source` | Explicit roles | Result |
| --- | --- | --- |
| absent | absent | reject: no input |
| present | absent | discover and validate the constructor's complete source profile |
| absent | present | preserve the constructor's explicit-file partial-profile behavior |
| present | present | source supplies unoverridden roles; explicit roles replace matching discovered roles; validate the final merged profile |

ChEBI's `from_obo(source, ...)` always has a primary source because OBO is its
selected representation. Its optional `sdf` is an overlay. The full four-mode
matrix applies to ChEBI table construction.

### Resolution and validation order

Every source-overlay constructor follows this observable order:

1. validate the source transport, directory, or archive and reject unsafe
   members;
2. identify which logical roles have explicit replacements;
3. discover only the unoverridden source roles needed for the selected profile;
4. normalize every final physical input and reject one physical file assigned
   to multiple final roles;
5. validate each explicit or discovered input under its role;
6. validate completeness and cross-file biological invariants against the
   final merged inventory; and
7. construct provenance only from that final inventory.

Therefore a source may omit a required role when that role is explicitly
provided. A missing unoverridden required role still fails. A discovered file
for an overridden role is not parsed, validated as a data input, or recorded as
provenance. Explicit `None` means no override; it does not exclude a role found
in `source`.

For roles accepting a sequence or directory, one explicit value replaces the
entire discovered role collection. Overlay never appends batches implicitly.
Archive provenance retains deterministic `archive::member` identity for the
members actually used.

### Release identity and metadata

The caller asserts that an explicit overlay belongs with the base source.
Bioextract validates authoritative release markers when the formats provide
them and rejects a detectable conflict. It cannot manufacture proof for files
whose formats carry no release identity, and it does not infer identity from
paths.

No new public `source_mode` metadata key is introduced. The final
`_bioextract.source_file` inventory already records the inputs that determine
the publication. Existing `scope` or completeness fields continue to describe
available capabilities, not how arguments were supplied.

## Slice 1: Rhea Constructor Convergence

Replace the two source-building entrypoints with:

```python
RheaDatabase.from_files(
    source=None,
    *,
    rdf=None,
    directions=None,
    relationships=None,
    obsolete_reactions=None,
    reaction_smiles=None,
    sdf=None,
    chebi_names=None,
    chebi_ph7_3_mapping=None,
    xrefs=None,
    uniprot_sprot=None,
    uniprot_trembl=None,
)
```

Remove `RheaDatabase.from_release` observably. `source` is positional or
keyword and may name an extracted Rhea release directory, zip archive, or tar
archive. Compression continues to be detected from content.

With no source, the existing explicit partial-capability matrix and scopes
remain unchanged. With a source, the final inventory must be a complete release
after overlay: unexposed release-only roles such as the license, release
properties, EC mapping, and GO mapping remain required; an exposed role may be
supplied explicitly instead. A source-backed overlay retains `scope="release"`
because the final capabilities are complete.

Focused verification covers directory and archive source-only builds, every
explicit role group, source plus one and multiple replacements, an absent
overridden source role, an absent unoverridden role, invalid explicit input,
cross-file mismatch, physical-file reuse, final provenance, release identity,
exact signature, and absence of `from_release`.

```python
KEGGDatabase.from_metabolic_files(

```

Remove `KEGGDatabase.from_metabolic_release` observably. `source` accepts the

An explicit entry directory, batch, or sequence replaces the complete
discovered `*_entries` collection for that family. Source-backed construction
sets the existing complete-release state only after final merged validation.
`release_version` remains caller-declared unless authoritative source content

Focused verification covers directory and archive parity, explicit partial

KEGG BRITE, organism mapping, and `from_duckdb()` are independent products and
do not change in this slice.

## Slice 3: ChEBI Representation Convergence

Remove the ambiguous `ChEBIDatabase.from_release` entrypoint and retain two
explicit representation contracts:

```python
ChEBIDatabase.from_obo(
    source,
    *,
    sdf=None,
    chemont_obo=None,
)

ChEBIDatabase.from_table_files(
    source=None,
    *,
    compounds=None,
    names=None,
    relations=None,
    secondary_ids=None,
    database_accessions=None,
    structures=None,
    chemical_data=None,
    chemont_obo=None,
)
```

`from_obo(source)` accepts an exact OBO input or a directory/archive containing
exactly one selected ChEBI OBO candidate. It may discover the matching ChEBI
SDF supplement; explicit `sdf` replaces that supplement. `chemont_obo` remains
an explicit independent supplement.

`from_table_files(source)` discovers the official table profile from a
directory or archive. Explicit table roles replace discovered roles and the
final profile must contain `compounds`. Without a source, the current explicit
table behavior remains available with `compounds` required.

The selected method determines the representation. A directory or archive
containing both OBO and tables does not trigger hidden OBO-versus-table
precedence. Duplicate candidates for a selected role fail instead of silently
choosing the first match. Directory and archive discovery must have equivalent
role and provenance semantics.

Focused verification covers each representation, directory and archive
discovery, explicit supplement and role replacement, ambiguous candidates,
missing compounds, safe archive handling, final provenance, unchanged
relations and selections, exact signatures, the `path` to `source` rename on
`from_obo`, and absence of `from_release`.

## Resources That Do Not Converge Further

- eggNOG already uses the representation-specific `from_sqlite(source)`.
- WikiPathways already uses `from_gmt(source, *, species, glob)`.
- UniProt constructors expose representation-specific or exact caller-owned
  roles by design.
- STRING, Reactome, and OmniPath retain explicit heterogeneous partial bundles;
  they have no duplicate release constructor to remove.
- GO OBO, KEGG BRITE and mapping, and InterPro/Pfam retain their
  representation-specific entrypoints.
- Publication readers always retain `from_duckdb(path)` as a separate
  lifecycle boundary.

## Dependency Graph And Review Splits

The intended delivery sequence is:

1. **Plan and archive update** — this documentation-only change records the
   accepted contract, archives the completed predecessor, and updates current
   navigation. It runs link/readback and diff checks, not the full Python gate.
2. **PR A: runtime budget** — repository validation environment, runtime
   probes, focused tests, and testing/runbook documentation.
3. **PR B: Rhea** — common overlay semantics and Rhea migration.
4. **PR C: KEGG metabolic** — independent metabolic migration on the merged
   common contract.
5. **PR D: ChEBI** — representation-specific migration after the common
   vocabulary is stable.
6. **Closeout** — current-doc search, exact-head full gate evidence, plan status
   and PR references. Fold this into PR D when possible; a separate docs-only
   closeout does not rerun an unchanged executable gate.

The host/AO admission and containment change is a separate cross-project task
owned by its control-plane repository. It may proceed in parallel after the
runtime baseline is measured, but later bioextract gates remain serial with a
budget of one until authoritative host readback proves the external control.

Each code PR owns one public contract or one harness boundary. The constructor
PRs do not form one large branch, and no PR writes formal publications or
downstream catalog files.

## Verification And Acceptance

### Runtime slice

Run the focused runtime tests under the default and constrained budgets, then:

```console
BIOEXTRACT_TEST_THREADS=1 pdm run check
```

Acceptance requires every loaded native pool to stay at or below one, every
stage to finish without resource-exhaustion errors, and the process-tree
measurement to be recorded without claiming an exact NLWP equality.

### Constructor slices

During each slice, run its integration tests, resource publication-contract
tests, API signature and docstring tests, followed by the serialized complete
gate:

```console
BIOEXTRACT_TEST_THREADS=1 pdm run check
```

Acceptance requires:

- source-only, explicit-only, source-overlay, and rejected-input behavior to be
  fixed by tests where the constructor supports those modes;
- exact public signatures and observable absence of removed constructors;
- final provenance to omit replaced source inputs and retain every used input;
- unchanged publication table, column, metadata, schema-version, selection,
  and read-only reopen behavior; and
- no stale current call sites or examples in `src/`, `tests/`, root `README.md`,
  current architecture, or current testing documents.

Historical archived documents may retain old calls only behind an explicit
historical or superseded marker.

### Documentation-only changes

The plan, archive move, and final closeout use targeted relative-link readback,
stale-reference search, `git diff --check`, and rendered-content inspection.
They do not run `pdm run check` unless they also change executable code or a
repository gate. Remote CI may still execute its configured canonical workflow.

## Risks, Rollback, And Cleanup

| Risk | Control |
| --- | --- |
| Native libraries read limits before the harness applies them | start repository validation through a pre-import environment boundary and verify in a fresh subprocess |
| A library creates helper threads beyond its worker pool | distinguish pool limits from NLWP and rely on external cgroup containment for hard process-tree control |
| Parallel AO workers multiply otherwise bounded pools | serialize full gates immediately; add host-owned admission before claiming aggregate enforcement |
| Overlay combines files from different releases | validate authoritative content markers when available, document caller assertion otherwise, and never infer identity from paths |
| Discovery silently chooses an ambiguous candidate | deterministic role resolution with duplicate-candidate errors |
| Explicit entry collections accidentally append to source entries | whole-role replacement tests for every sequence-capable role |
| Removing constructors breaks stale callers | pre-v1.0 exact absence tests and complete current-doc/call-site search; no compatibility layer |
| A resource migration changes publication output | contract and integration parity checks against the final merged inventory |

Each implementation PR is independently revertible. Rollback restores its
former constructor or harness behavior by reverting that PR; it does not add a
forwarding alias. Temporary archive extraction and runtime-measurement artifacts
use local temporary directories and are removed after their owning check.
