# Cross-resource execution convergence: P0 inventory

Date: 2026-08-14
Scope: repository source and focused test fixtures only; no CephFS scan and no
full 11,782-organism build.

This record freezes the implementation invariants and the physical classes used
by the accepted execution-performance plan. It is an inventory, not a speedup
claim. The fixed KEGG development workload remains the 1,000-organism protocol
from the preceding KEGG plan.

## Physical classes

| Class | Maintained paths | Current boundary | Verification |

| Explicit global materialization | GO closure/topology and compact selection anchors | materialized state is named, selection-scoped, replayable, and never a default flat high-cardinality result | GO/selection tests and empty-anchor probes |

## Eager-risk inventory

The following patterns were searched with bounded repository `rg` queries:

- `register_materialized_source` remains only on explicit parser/source or
  small/global exceptions; migrated publication relations use
  `register_replayable_source`.
- `fetchall()` remains in metadata validation, compact identifier anchors, and
  small/global parsers. It is not used to produce the migrated high-cardinality
  relation batches.
- `list(rows)` was removed from the Rhea publication writer. The static checker
  rejects it in maintained source code.
- No public `max_rows` or `batch_size` parameter was introduced. Batch size is
  an internal request hint and row limits are Polars plan semantics.

## Frozen behavior invariants

- Public relation methods return native, replayable `polars.LazyFrame` objects;
  callers own terminal `collect()`/`sink_*()` decisions.
- Projection, supported domain filters, residual predicates, safe slices,
  replay, and early-close must preserve complete biological output.
- Empty selections must not open downstream high-cardinality relation readers.
- One selection copy shares one compact anchor; an expanded input-by-relation
  result is not cached as the selection's default state.
- Source/publication parity, capability errors, taxon/species scope, metadata
  v2, and existing null/list semantics remain unchanged.
