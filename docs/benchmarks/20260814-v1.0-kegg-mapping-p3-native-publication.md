# KEGG Mapping P3 Native Publication Benchmark

Date: 2026-08-14
Status: fixed 1,000-organism P3 candidate accepted; full source build remains
outside this optimization gate

## Decision

The DuckDB-native publisher is accepted for the fixed optimization scope. It
uses eight private organism hash windows, explicit multi-file role scans,
SQL validation, per-key nested aggregation, and a target-adjacent temporary
spill directory. It does not expose a row limit, batch size, memory setting, or
window parameter.

Compared with the recorded P1 local reference (252.64 s, 3.10 GB peak RSS),
three local runs took 157.53–203.19 s and used 1.92–1.96 GB peak RSS. The
median is 34.1% faster; even the slowest run is 19.6% faster. All runs stayed
below the P1 RSS budget, used no temporary spill bytes, and left no staging or
temporary directory after success or injected failure.

The source is a copied fixed 1,000-organism scope for local timing only. The
normalized scope hash is
`31998ba5b43d83ec1b906cf7078e58389befefae08862849c343bf29c8fffa85`; the
source contains 5,002 role files and 726,258,291 bytes. No full 11,782-organism
build was run.

## Resource evidence

DuckDB 1.5.5 ran with eight threads, a private memory bound of 270,308,530,176
bytes, and a per-run maximum temporary-directory size of approximately 153 GB.
The measured peak temporary spill was zero. Peak open descriptors were 19–22;
peak staged database bytes were 242–248 MB. The high default host thread count
(192 in this environment) was capped internally because inheriting it caused a
100-organism RSS of about 3.4 GB and 102 open descriptors.

Compact fixtures additionally cover zero-byte roles, exact duplicate edge
deduplication, malformed rows, conflicting metadata, stage preservation, and
private-relation cleanup. Duplicate relationships are silently idempotent;
conflicting gene metadata is fatal.

## I/O qualification

Four bounded direct-CephFS observations ranged from 165.36 s to 251.24 s while
RSS remained about 2.1 GB and spill remained zero. This spread is treated as
filesystem/cache variance, not algorithmic evidence. The local copied scope is
the acceptance basis; CephFS is recorded as an operational observation only.

The reverse-selection benchmark on the native publication reconciled every
UniProt and NCBI Gene checksum against a temporary flat SQL lookup. Aggregate
public selection took 4.71–6.29 s for the tested input sizes; this result does
not justify adding a fourth physical lookup table.
