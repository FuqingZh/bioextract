# Cross-resource execution convergence: P2 candidate evidence

Date: 2026-08-14
Status: implementation evidence; no production-scale speed claim

This record closes the P2 classification for the current source tree. The
checks use local fixtures and publication contracts. They prove bounded,
replayable execution and output parity; they do not substitute for a later
large-snapshot benchmark with child-process RSS measurement.

## Candidate decisions

| Resource | Physical decision | Evidence | Residual boundary |
| --- | --- | --- | --- |
| STRINGDB | Keep regular aliases/links source paths as native Polars lazy plans; selected anti-joins reuse the native mapping plan | 26 integration tests pass; repeated edges/mappings/unmatched collection passes under `BIOEXTRACT_TEST_THREADS=1` | No real STRING release snapshot was timed in this slice |
| OmniPath | Keep native source scans and replayable relation batches; do not add a materialized relation cache | 15 integration tests and strict static checks pass | File-size scale evidence remains external-snapshot work |

| Reactome | Use native Polars source scans for pathway, mapping, relation, and selected source queries; publication queries use DuckDB Arrow batches | 12 integration tests pass with zero deprecation/resource warnings | The complete source-to-publication writer remains a separate benchmark |
| InterPro | Use bounded protein2ipr parser batches for source mappings and selected mappings/unmatched IDs; publication mapping uses Arrow batches | InterPro contract/integration tests pass; request-aware static checks pass | XML/Pfam lookup metadata remains an explicit small/global parser boundary |
| GO | Keep ancestor closure and topology as explicit global materialization | GO integration tests pass; no fake streaming wrapper was introduced | A larger ontology benchmark is required before revisiting this boundary |

The existing ChEBI, KEGG metabolic, Rhea, UniProtKB, and WikiPathways
request-aware paths were covered by their focused integration suites. Rhea
publication rows are inserted through bounded iterator slices; WikiPathways GMT
selection parsing now yields bounded selected rows rather than first building a
complete selected mapping frame.

## Integrity observations

- No public execution limit or collection wrapper was added.
- Native source plans remain composable Polars `LazyFrame` objects.
- Publication readers open a fresh connection per execution and close Arrow
  readers in `finally` blocks.
- Empty selections retain typed schemas and do not open downstream relation
  readers where the resource has a compact anchor.
- The single-thread validation run caught a nested-Polars execution hazard in
  STRING unmatched selection. The implementation now reuses its native mapping
  plan rather than collecting a plugin-backed relation inside another lazy
  plan.

## Decision

Accept the P2 candidates for correctness and physical classification. Do not
claim a percentage speedup or production RSS improvement from this record.
Those claims require the fixed publication identities, repeated cold/warm
measurements, first-batch counters, and child-process RSS protocol defined by
the implementation plan.
