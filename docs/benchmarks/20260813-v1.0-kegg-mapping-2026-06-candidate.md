# KEGG Mapping 2026-06 Candidate Benchmark

Date: 2026-08-14
Status: scoped candidate passed; full-build performance gate remains open

## Outcome

The aggregate three-table design removes Cartesian expansion and remains
memory-bounded on measured scopes. The complete 11,782-organism publication did
not finish within the final three-hour safety boundary, so this evidence does
not authorize a formal full publication or package release.

The bottleneck is full-build throughput across 58,910 organism role files plus
aggregate construction and DuckDB insertion, not a user-visible row limit. The
implementation now amortizes inserts at an internal fixed row target; it does
not expose `batch_size`, `max_rows`, or truncated semantics.

The two-organism run sampled at most seven open file descriptors. Its output

`a9c3e580995142a733b1c773a935e5070a32d5726aa1e603a3b46c0e32f7d4d4`.
The only validation issue was one file-level warning for two exact duplicate

The final externally terminated full attempt left no committed destination. At
termination its uncommitted stage was about 1.92 GiB with an 11.40 MiB WAL; both
files were identified and removed. Normal
parser/validation failures are covered by tests that prove `finally` cleanup
and preservation of the previous target; abrupt process destruction cannot
promise cleanup of an uncommitted staging file.

The P1 Arrow candidate was reconciled against the pre-P1 fixed 100-organism
publication with bidirectional `EXCEPT ALL`: `organism`, `gene_annotation`, and
`ko_annotation` each returned zero differences. The fixed 1,000 candidate
retained the expected source file count, source bytes, capability inventory,
and row counts. A bounded four-worker complete-parser experiment was rejected:
on the same local 100-organism copy it took 204.95 s and 2.28 GiB RSS versus
82.19 s and 1.24 GiB RSS with one worker.

## Reverse Selection

On the unscoped `hsa` + `mmu` publication, public nested lookup for 1, 100, and
10,000 UniProt or NCBI Gene IDs took 0.260–0.311 seconds. A temporary normalized
lookup baseline took 0.031–0.243 seconds, excluding its 0.102–0.111 second build.
Every input size and namespace reconciled match counts and checksums.

The measured absolute public latency is below one second and does not yet
justify adding a fourth physical lookup table. This decision applies only to
the measured two-organism serving scope. Full-publication unscoped selection
cannot be accepted until a full candidate exists.

## Decision

- Accept the public LazyFrame, nested schema, one-pass provenance, scoped
  publication, and aggregate-only serving design in code.
- Hold formal all-organism publication and package release.
- Use one exact 1,000-organism scope for all optimization and profiling work;
  reject comparisons when its scope hash or biological evidence changes.
- Accept the P1 Arrow construction for the candidate implementation; treat
  CephFS wall-clock measurements as I/O-sensitive observations until repeated
  under a controlled release window.
- Reject complete-parser thread concurrency. A raw-byte-only prefetch remains
  a future hypothesis, not an accepted implementation.
- Do not rerun the all-organism source during the optimization loop. A later
  full offline build is a separately scheduled release-readiness gate after the
  implementation candidate is frozen.
