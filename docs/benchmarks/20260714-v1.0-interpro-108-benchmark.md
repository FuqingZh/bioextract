# InterPro 108.0 Tidy Publication Benchmark

Version: v1.0
Date: 2026-07-14
Status: superseded historical Parquet baseline

These measurements predate the unified DuckDB writer. They remain useful as
historical input-scale and relation-count evidence, but do not measure unified
DuckDB output size, reopen validation, or selected-ID query behavior. A fresh
full-snapshot unified run is required before establishing that baseline.

```text
/cephfs_data/genostack_v3/genostack_php/public_file_data/database/bioinfo/resources/interpro/mapping/108.0/raw/protein2ipr.dat.gz
/cephfs_data/genostack_v3/genostack_php/public_file_data/database/bioinfo/resources/interpro/mapping/108.0/raw/interpro.xml.gz
```

## Canonical Mapping

Validated output:

```text
/cephfs_data/genostack_v3/genostack_php/public_file_data/database/bioinfo/resources/interpro/mapping/108.0/tidy/mapping.parquet
```

Observed on 2026-06-08:

- parquet size: about 13 GB
- row count: 1,175,529,272
- schema: `UniProtId`, `InterProId`, `InterProName`, `InterProType`,
  `MemberDb`, `MemberDbId`, `Start`, `End`
- `POLARS_MAX_THREADS=8`; thread count stayed around 31
- RSS was observed up to about 17 GB

The written parquet schema, row count, and deterministic head sample were read
back successfully.

## Compact Pfam Assets

Observed on 2026-07-14 from the two raw inputs above; the full
`mapping.parquet` was not a build input:

- direct input sizes: 17,001,556,679 bytes and 40,794,714 bytes
- `protein_term.parquet`: 230,896,674 unique protein-term rows,
  154,020,515 proteins, 26,620 Pfam IDs, 1,174,600,833 bytes
- `term.parquet`: 26,620 rows, 166,669 bytes, no missing or conflicting names
- `term_xref.parquet`: 26,620 rows, 370,453 bytes, no incomplete references
- elapsed time: 8 minutes 11.6 seconds with `POLARS_MAX_THREADS=8`
- maximum RSS: 60,171,304 KiB, about 57.4 GiB
- every raw `InterProId + PfamId` pair matched the XML member relationship
- deterministic 1,000-protein sample: 1,419 compact rows, exactly equal to the
  PFAM projection of the canonical mapping
- warm-cache selection of the same 1,000 IDs: approximately 0.033 seconds

The peak RSS is an observed publication requirement for this implementation,
not a general API limit. See the current
[InterProDatabase test standard](../testing/interpro-db.md) for acceptance criteria.
