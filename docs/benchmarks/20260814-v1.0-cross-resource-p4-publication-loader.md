# Cross-resource execution convergence: P4 publication-loader evidence

Date: 2026-08-14
Status: implemented bounded-loader checks; no full publication rebuild claim

## Bounded producer evidence

The shared publication contract now has a one-shot producer test. A source
that yields two batches (`[1, 2]`, `[3, 4]`) is passed to the DuckDB writer;
the writer consumes both batches and records the emitted batch sizes without
pre-buffering the complete relation. The focused lazy-source suite passes all
seven cases, including this writer lifecycle probe.

Rhea publication insertion no longer calls `list(rows)`: participant rows are
generated and inserted in bounded slices. WikiPathways GMT parsing yields
validated pathway/gene records incrementally, and selection mappings emit
bounded selected batches. Reactome regular source relations use native
Polars scans instead of converting the complete source relation to a frame.

## Retained strategies

- Native Polars scans remain the source strategy for regular delimited files.
- Parser-to-Arrow or parser-to-bounded-frame paths remain domain-owned for
  DAT, XML, GMT, SQLite, OBO, SDF, and KEGG formats.
- The shared `_publication.py` Parquet stage remains for the measured
  multi-pass/recovery publication boundary; it is not silently presented as a
  streaming source relation.
- Small/global algorithms such as GO closure retain explicit materialization.

## Decision

Accept the P4 lifecycle and bounded-consumption contract. Do not claim a
whole-publication wall/RSS improvement: no new large snapshot build was run in
this slice, and the previously observed full KEGG development build remains
outside the authorized 1,000-organism protocol.
