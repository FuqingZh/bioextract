# Cross-resource P5: v2-compatible joint_omics experiment

Date: 2026-08-14
Status: bounded v2-compatible evidence; P5a candidate accepted for further
review, not a formal publication or release benchmark

## Decision

The initial candidate lowered CPU time and peak RSS but increased end-to-end
wall time by about 10.7%. The P5a Rhea-anchor follow-up removed that measured
regression on the same bounded workload: wall time, CPU time, and peak RSS are
all below the frozen baseline, with stable biological outputs. The follow-up
is accepted as a bounded algorithmic candidate for further review, not as a
formal release-scale claim.

## Scope and isolation

The run used the same 23,362-feature protein/metabolite inputs as the frozen
joint_omics v04 baseline and five measured repetitions after one warmup. The
five available DuckDB publications were hard-linked into a temporary resource
tree under `/tmp/bioextract-p5-v2`; only the copied `_bioextract` metadata was
repaired from metadata v1 to the current metadata-v2 reader contract. The
official catalog bytes and logical selectors were copied unchanged into the
temporary catalog. No CephFS publication, catalog, or source file was changed.

The downstream v04 harness was copied into `/tmp` and its single hard-coded
metadata-version expectation was temporarily changed from `1` to `2` so that
the experiment could exercise the current reader. This is a compatibility
probe, not a joint_omics repository change or a downstream release decision.
The experiment does not introduce a `manifest.lock` or `biofetch` dependency
into bioextract.

## Initial candidate (before P5a)

All values are medians of the five measured repetitions. RSS is the child
process maximum resident set size reported by `/usr/bin/time -v`.

| signal | frozen v04 baseline | current candidate | candidate / baseline |
| --- | ---: | ---: | ---: |
| wall time (s) | 13.03 | 14.42 | 1.107 |
| CPU time (s) | 102.70 | 64.85 | 0.631 |
| child peak RSS (KiB) | 2,003,616 | 715,044 | 0.357 |

This intermediate candidate was rejected for wall-time regression and is kept
to make the optimization decision auditable.

## P5a Rhea-anchor follow-up

The follow-up caches one thread-safe selection-owned `input_id -> rhea_id`
anchor, short-circuits empty anchors before downstream selection registration,
and registers the compact anchor through DuckDB's Arrow boundary. It does not
add a public execution limit, persistent index, or publication table.

All values are medians of five measured repetitions on the same input scope.

| signal | frozen v04 baseline | P5a candidate | candidate / baseline |
| --- | ---: | ---: | ---: |
| wall time (s) | 13.03 | 8.30 | 0.637 |
| CPU time (s) | 102.70 | 54.33 | 0.529 |
| child peak RSS (KiB) | 2,003,616 | 1,011,440 | 0.505 |

The Rhea backend component alone moved from the pre-follow-up median of 8.71 s
wall and 37.47 s CPU to 3.86 s wall and 26.40 s CPU. Its output rows and
schemas remained unchanged. The five P5a full-run timing rows were:

## Output reconciliation

The following stable biological artifacts matched the frozen baseline byte for
byte in every candidate repetition:

- `data-mapping_entities.parquet`
- `data-mapping_overview_plot.parquet`
- `data-mapping_pathways.parquet`
- `data-mapping_reactions.parquet`
- `stats-mapping_coverage.tsv`
- `stats-mapping_issues.tsv`

Temporary resource paths, metadata descriptors, and manifest-like files were
not compared as biological output because the experiment deliberately used a
temporary v2-compatible resource tree.

## Gate interpretation

The P5a evidence closes the bounded question “does the candidate reduce
materialized memory, repeated CPU work, and wall time on a compatible
downstream-shaped run?” with a qualified yes. It does not close “does the
candidate improve end-to-end wall time on a formal release publication?”; that
formal run has not been authorized or performed.

Any next run must preserve the exact input scope, output reconciliation, all
repetitions, and child-process RSS measurement. The measured Rhea path is now
accepted without introducing a persistent index, spool, or public API knob.
A formal release-scale gate still requires a separately authorized metadata-v2
publication rebuild and downstream contract coordination. bioextract remains
independent of the producer of those artifacts.
