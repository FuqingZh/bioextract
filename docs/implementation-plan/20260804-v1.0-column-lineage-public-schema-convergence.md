# bioextract v1.0 Column Lineage And Public Schema Convergence Plan

Version: v1.0
Date: 2026-08-04
Status: planned
Authority: [Domain Access Architecture](../architecture/20260729-v1.0-domain-access-architecture.md) and [Materialized Dataset Contract](../architecture/tidy-dataset-contract.md)

## Summary

Converge every implemented resource on one column-ownership and public-schema
contract before bioextract v1.0:

- a value copied one-to-one from an official two-dimensional relation keeps
  its exact official header;
- every bioextract-created value uses lowercase `snake_case`;
- the shared selection protocol becomes `input_id`, `input_namespace`,
  `group_id`, `reason`, and `match_type`;
- OBO, RDF, XML, SDF, GMT, headerless records, joins, identifier
  normalization, prefix decomposition, canonical endpoints, and aggregates
  produce bioextract-owned `snake_case` fields;
- `_bioextract.column_mapping` records only unavoidable mappings from real
  official headers, not implementation-local PascalCase-to-snake_case steps;
- classmethod factories retain `from_*`; `register_*` is reserved for a future
  API that actually mutates an existing registry or query context;
- source scans expose official relations lazily, while selections continue to
  package resource-owned identifier resolution, grouped fan-out, relationship
  traversal, and unmatched accounting; and
- pre-v1.0 names are removed directly without duplicate aliases, deprecated
  columns, or legacy publication readers.

The storage strategy does not change. eggNOG, STRING, and OmniPath remain
official/native direct adapters. Materialized logical products remain one
bioextract-owned DuckDB with `_bioextract` provenance. Parquet is not restored
as a canonical publication format.

## Goals

1. Make every public column name explainable from column-level lineage rather
   than a blanket style conversion.
2. Give all resources one query-friendly selection protocol that matches
   Polars and DuckDB relations.
3. Remove cosmetic aliases and adapters that translate a stable physical
   `snake_case` relation back to PascalCase.
4. Correct provenance that currently describes synthetic parser names as
   official source headers.
5. Preserve the existing grouped unique-resolution and selection-local cache
   contracts.
6. Deliver independently reviewable resource slices with focused tests and
   bounded real-snapshot acceptance.

## Non-goals

This plan does not:

- add downloads, resource discovery, catalogs, or dependencies on biofetch or
  downstream applications;
- add a generic Database base class or generic `query()` facade;
- add a persistent decompression cache;
- convert direct-only sources to DuckDB merely for uniformity;
- add a general-purpose lineage catalog or a new `_bioextract` metadata table;
- infer releases, source schemas, namespaces, or taxa from paths or filenames;
- preserve pre-v1.0 result headers through duplicate columns or compatibility
  views; or
- perform official CephFS replacement as an implicit side effect of a code PR.

## Settled Column-Lineage Contract

Column ownership is decided per column, not per output table. A filtered,
joined, or grouped result may contain both official source-owned columns and
bioextract-owned columns.

### Source-owned columns

Keep the exact official header, including case and punctuation, when a column:

- comes from exactly one official source column;
- retains the source value, identifier namespace, unit, null meaning, and
  biological semantics; and
- is not split, merged, coalesced, normalized to another representation,
  canonicalized across alternative source columns, or aggregated.

Row filtering, sorting, membership joins, and grouped fan-out do not by
themselves change ownership. Representation-level parsing that faithfully
decodes the official logical value, such as parsing an integer or official
null marker, may retain the official header. A transformation that changes
the represented value, such as lowercasing an identifier, stripping a prefix,
or translating a namespace, creates a derived column.

Public `scan_*()` methods preserve all supported official columns in official
order. A high-level `extract_*()` result preserves each source-owned column it
carries even when the relation also contains derived fields.

### Bioextract-owned columns

Use stable lowercase `snake_case` for values or semantics created by
bioextract, including:

- caller and group lineage;
- normalized identifiers;
- values parsed from headerless or structured records;
- fields split from, combined from, or coalesced across source fields;
- cross-table relationship results;
- namespace translations and canonical targets;
- canonical endpoints that may originate from either source endpoint;
- hierarchy depth, path, direction, or role derivations; and
- aggregates across several official records.

The fact that a method is named `extract_*()` does not make every returned
column derived. Ownership follows the value lineage.

### Shared selection protocol

All single and grouped selections use these exact shared fields when the
corresponding concept is present:

| Previous pre-v1.0 name | Final v1.0 name | Meaning |
| --- | --- | --- |
| `InputId` | `input_id` | Normalized caller identifier retained for result lineage |
| `InputNamespace` | `input_namespace` | Namespace used to interpret `input_id` |
| `GroupId` | `group_id` | Normalized caller-owned group label |
| `Reason` | `reason` | Stable unmatched or exclusion reason code |
| `MatchType` | `match_type` | Exact, secondary, replacement, or other resource-defined match route |

Related bioextract-created fields such as `anchor_type`, `anchor_id`, and
`depth` follow the same `snake_case` rule. Reason-code values do not change.

Grouped outputs place `group_id` first. Selection results then place
`input_id` and `input_namespace` when present, followed by source-owned columns
in official order and then remaining derived fields in their declared domain
order. Non-grouped outputs do not contain `group_id`.

### No cosmetic aliases

One relation must not expose both an official column and a cosmetic renamed
copy. Examples prohibited by this contract include:

```text
source + MapSource
combined_score + Score
protein1 + Protein1
enzyme + SourceId
```

When a normalized or translated value is separately useful, it receives a
specific derived name and is emitted only when its distinct semantics are part
of the domain contract.

### Necessary official-header mapping

An official header may change only when it is empty, duplicated, conflicts
case-insensitively in DuckDB, contains a representation the target cannot
support, or otherwise cannot be queried safely. The owning source profile
defines the smallest deterministic mapping.

Every such mapping is recorded as:

```text
table_name
source_column
output_column
reason
```

in `_bioextract.column_mapping`. No generic sanitizer is applied. Unknown
official header changes are unsupported source schemas until an explicit
source profile is added.

`_bioextract.column_mapping` is not a general lineage registry. A derived
field that is born as `snake_case` does not create a mapping row. Metadata
schema v1 remains unchanged and no `_bioextract.column_lineage` table is added.

## Public Method And Lifecycle Naming

`from_*` remains the factory prefix because every constructor returns a new
Database handle from a caller-supplied representation:

```python
EggNOGDatabase.from_sqlite(source)
GODatabase.from_obo(source)
WikiPathwaysDatabase.from_gmt(source)
RheaDatabase.from_files(...)
RheaDatabase.from_duckdb(path)
```

`register_*` would imply mutating an already-existing connection, catalog,
registry, or SQL context by attaching a named object. No current Database API
has that lifecycle, so no constructor is renamed to `register_*`.

The public verb contract is:

| Prefix or method | Contract |
| --- | --- |
| `from_*()` | Construct a new handle from a declared source representation or publication |
| `scan_*()` | Return a lazy official or stable relation without eager materialization |
| `read_*()` | Materialize a declared relation eagerly |
| `select_*()` | Create an identifier-aware domain selection |
| `extract_*()` | Materialize a domain relation from a Database or Selection |
| `write_duckdb()` | Validate and atomically publish one logical product |
| `connect()` | Return a fresh caller-owned read-only native DuckDB connection |

`from_files()` remains only for a heterogeneous named bundle whose roles are
the caller-visible contract. Format-specific or homogeneous profiles retain
names such as `from_sqlite()`, `from_obo()`, `from_gmt()`,
`from_table_files()`, and `from_mapping_files()`.

## Current Resource Audit

### GO

- OBO records and ontology traversal are structured derivations.
- Existing `go_id`, `term_name`, `input_go_id`, edge, subset, ancestor, and
  depth fields already use the required style.
- No runtime schema migration or publication rebuild is required.

### ChEBI and ChemOnt

- Official ChEBI TSV publications continue to preserve exact official headers.
- OBO, SDF, and ChemOnt canonical relations remain stable `snake_case`.
- Selection extractors stop aliasing canonical DuckDB fields to PascalCase and
  adopt the shared selection protocol.
- A query-only migration does not require rebuilding an already-correct
  canonical publication. Any official TSV publication is rebuilt only if its
  validation shows incorrect header mapping.

### Rhea

- RDF, SDF, direction-aware participants, reaction relationships, and combined
  cross-reference relations remain derived `snake_case` schemas.
- Selection extractors return physical domain names directly and adopt the
  shared selection protocol.
- The existing Rhea publication schema does not change solely for the Python
  extraction migration; no rebuild is required unless a separate validation
  finding changes physical schema or provenance.

### UniProt

- UniProtKB DAT and FASTA relations remain derived `snake_case` publication
  tables.
- Knowledgebase selection extractors stop translating those fields to
  PascalCase.
- `idmapping_selected.tab` is headerless. Its parser must create final
  `snake_case` columns directly rather than synthetic PascalCase columns.
- `preserve_source_headers=("mapping",)` is removed from the headerless
  idmapping writer.
- UniProt idmapping publications are rebuilt; knowledgebase publications are
  rebuilt only if their physical or provenance validation changes.

### KEGG

- BRITE JSON and metabolic ENTRY/tag relations remain derived `snake_case`.
- Metabolic selections adopt the shared protocol and stop PascalCase output
  aliases.
- Organism mapping conv/link/list inputs are headerless. The parser creates
  final `snake_case` mapping fields directly.
- Synthetic KEGG mapping rows are removed from `_bioextract.column_mapping`.
- KEGG organism mapping publications are rebuilt. BRITE and metabolic
  publications are rebuilt only if a resource-local change affects stored
  schema or provenance.

### Reactome

- UniProt2Reactome, pathway, and hierarchy files are headerless positional
  relations.
- Parsers create final `snake_case` fields directly; direct and reopened
  extractors expose the same schema.
- Synthetic PascalCase-to-snake_case provenance rows are removed.
- Reactome publications are rebuilt and their exact physical schema and empty
  or necessary-only column-mapping inventory are validated.

### WikiPathways

- GMT records are positional, and their first field is decomposed into pathway
  metadata. All produced domain columns are derived.
- Direct, reopened, and selection outputs use the same `snake_case` fields.
- Reopened publications are not translated back to PascalCase.
- Synthetic column-mapping rows are removed and WikiPathways publications are
  rebuilt.

### InterPro and Pfam

- `protein2ipr.dat` is headerless; InterPro XML and compact Pfam relations are
  parsed and joined derivations.
- Mapping and Pfam frames are born in final `snake_case` rather than converted
  at the writer boundary.
- Direct, reopened, and selection output schemas agree.
- Synthetic column-mapping rows are removed and InterPro publications are
  rebuilt.

### eggNOG

- eggNOG remains direct-only through the official SQLite representation.
- One-to-one official SQLite columns retain their names where carried, such as
  `name`, `og`, `level`, `description`, and `COG_categories`.
- The protein `ogs` decomposition, COG-category expansion, and optional
  headerless COG function lookup produce explicit derived fields such as
  `cog_category`, `cog_class`, and `cog_name`.
- `read_cog_fun()` and selection outputs adopt the shared protocol and the
  mixed source-owned/derived schema.
- No DuckDB publication or publication rebuild is introduced.

### STRING

STRING remains a direct adapter with two optional source roles.

The Database handle exposes:

```python
database.available_resources
database.scan_aliases()
database.scan_links()
database.select_ids(ids, namespace="alias")
database.select_ids(ids, namespace="string")
database.select_groups(ids_by_group, namespace="alias")
database.select_groups(ids_by_group, namespace="string")
```

`scan_aliases()` and `scan_links()` return all supported official columns in
official order. Alias profiles distinguish the actual official protein-ID
header, including hash-prefixed and plain variants, through validated content.
The profile is not inferred from a filename or release value.

Alias selection resolves globally unique normalized input IDs once, applies
source ranking once, and fans results back to groups. Its result contains
`group_id` when grouped, `input_id`, and the selected official protein-ID,
`alias`, and `source` columns. Private normalized lookup values do not replace
the official output cells.

`namespace="string"` accepts direct STRING protein identifiers and makes a
links-only handle usable for edge and unmatched extraction. An alias-mapping
extractor on a links-only direct-ID selection raises `CapabilityError` because
no official alias relation exists.

`scan_links()` preserves official rows exactly. `extract_edges()` exposes one
canonical undirected edge with:

```text
group_id                 # grouped selections only
string_id_a
string_id_b
combined_score
```

The canonical endpoint fields are derived because either may originate from
`protein1` or `protein2`. Reverse `A B` and `B A` rows must agree on
`combined_score`; disagreement raises `IntegrityError`. Exact duplicates and
agreeing reverse rows collapse to one edge. A self-link is retained once with
equal canonical endpoints. Score-conflict validation occurs before
`with_min_combined_score()` filtering so a threshold cannot hide inconsistent
source observations. The unchanged official confidence value retains the
header `combined_score`; no silent `max()` aggregation remains.

Aliases and links supplied together must have compatible taxon prefixes based
on content. Disjoint non-empty taxa raise `IntegrityError`; subset capability
bundles are accepted. Plain and gzip transport are detected by content. A
logger warning explains repeated decompression cost without persisting a
cache.

### OmniPath

OmniPath remains a direct adapter with optional `enzsub` and `interactions`
roles and exposes:

```python
database.available_resources
database.scan_enzsub()
database.scan_interactions()
database.select_ids(ids, namespace=...)
database.select_groups(ids_by_group, namespace=...)
```

Each source scan returns every supported official column in official order,
including evidence and provenance fields. Selection must not collapse records
that differ only in evidence.

Every source profile declares the endpoint namespaces represented by its
official fields. If a profile contains more than one supported namespace,
`namespace` is required and matching occurs only in that namespace. Source
construction rejects an unrecognized profile rather than guessing namespace
from values or filenames.

Enzyme-substrate extraction preserves unchanged official `enzyme`,
`substrate`, `residue_type`, `residue_offset`, and `modification` values. A
derived `target_site` may be added from residue type and offset, but it does
not replace the source fields. Interaction extraction preserves official
`source`, `target`, and evidence columns. Boolean decoding retains the official
`is_directed`, `is_stimulation`, and `is_inhibition` headers and nullable
meaning; unknown is never coerced to false.

The ordinary-filter convenience methods below are removed once source scans
are public:

```text
has_any_enzsub_relation()
has_any_interaction_relation()
has_any_enzsub_modification()
```

Grouped unique-resolution, resource selection, evidence preservation, and
unmatched accounting remain.

## Grouped Selection And Cache Invariants

Every `select_groups()` implementation keeps the existing set-oriented model:

```text
ids_by_group
    -> normalize group labels and input IDs
    -> resolve globally unique input IDs once
    -> compute unique matches and unmatched decisions once
    -> fan results back through group membership
```

The migration changes column names, not execution semantics:

- empty groups remain represented internally;
- duplicate membership within a group collapses;
- one normalized ID shared by several groups is resolved once;
- matches and missing IDs appear independently in every owning group;
- multiple terminals on one Selection reuse identifier mapping;
- no process-global or cross-Selection result cache is added; and
- source scan count does not grow with repeated group membership.

## Publication And Version Contract

The publication container, metadata schema, and read-only connection contract
remain unchanged:

```text
main.<domain_relation>

_bioextract.metadata
_bioextract.source_file
_bioextract.table_info
_bioextract.column_mapping
_bioextract.validation_issue
```

This repository is pre-v1.0. An affected resource adopts its final v1
resource schema directly; pre-convergence development publications are not
accepted through compatibility readers. No v2 or v3 is introduced merely to
preserve unpublished intermediate schemas.

`source_schema_profile` continues to identify the validated official source
grammar. It changes only when supported official headers or grammar change,
not because a derived output field is renamed. `resource_schema_version`
identifies the bioextract-owned relation contract and is updated or reset to
the final resource-specific v1 value when stored schema or required provenance
changes.

Formal publication replacement is a separate release operation after the
owning code PR passes. Builds use temporary local or explicitly scoped staging
paths first. A final `tidy/data.duckdb` is replaced atomically only with
explicit snapshot and destination scope. Existing formal files are retained
until the replacement passes identity, schema, row-count, provenance, and
domain smoke checks; this plan authorizes no automatic deletion.

## Test And Verification Contract

### Shared unit tests

- exact shared protocol fields and order;
- group-label and input-ID normalization;
- duplicate membership collapse and empty-group preservation;
- globally unique lookup input;
- grouped fan-out and unmatched fan-out;
- selection-local cache reuse; and
- removal of old protocol names.

### Resource contract tests

For every resource:

- classify each public output column as source-owned, derived, or shared
  protocol;
- assert exact header spelling, case, punctuation, order, and type;
- assert source-owned cell equality against official-format fixtures;
- assert no cosmetic alias pair exists;
- assert derived fields use `snake_case`;
- assert unknown source profiles fail without path inference; and
- assert direct and reopened schemas agree when both access modes exist.

### Publication tests

- exact main table and view inventory;
- resource and source schema identity;
- row-count and table-role agreement;
- `_bioextract.column_mapping` empty unless a real official header requires a
  declared mapping;
- no synthetic parser-name mapping rows;
- unchanged metadata v1 five-table inventory;
- read-only connection behavior; and
- staging failure leaves the previous destination intact.

### Real-snapshot smoke

External snapshot tests are opt-in, explicitly pathed, bounded to the owning
resource subtree, and excluded from the default hermetic gate. They record
source headers, selected identifiers, representative row counts, publication
identity, and domain-specific invariants without embedding CephFS paths as
library defaults.

Implementation PRs run focused tests while iterating and finish with:

```console
pdm run check
```

The documentation-only plan PR runs link/readback checks and:

```console
git diff --check
```

It does not run the full code gate because it changes no executable contract.

## Compatibility, Cleanup, And Risk

- This is a deliberate pre-v1.0 breaking convergence. Old PascalCase result
  fields and development publications are not compatibility promises.
- No result contains both old and new names. Users receive one canonical
  schema.
- Publication readers reject pre-convergence stored contracts when their
  physical schema or required provenance differs.
- Formal publications are not deleted by tests or code PRs. Replacement and
  prior-artifact cleanup remain explicit release actions.
- The largest mechanical risk is an incomplete cross-resource protocol rename.
  PR 2 therefore uses an exact old-name absence gate in addition to behavior
  tests.
- The largest semantic risk is mistaking a normalized or aggregated value for
  an unchanged official column. Resource contract tests compare values, not
  only names.
- The largest provenance risk is continuing to use `column_mapping` as a
  generic generated-field registry. Publication tests prohibit synthetic
  mapping rows.
- The largest performance risk is reintroducing per-group lookups while
  changing schemas. Existing unique-resolution and scan-count gates remain
  mandatory.

## Completion

This plan is complete only when:

1. the shared protocol is exclusively `snake_case` across all resources;
2. every public column has a tested source-owned, derived, or protocol role;
3. every official source scan preserves its supported header and order;
4. no cosmetic alias or artificial parser-name mapping remains;
5. all direct and reopened access paths agree on domain schema;
6. required formal publications are rebuilt, atomically delivered, and read
   back from their final destination;
7. focused tests and `pdm run check` pass on every implementation head;
8. resource architecture, testing, examples, and this plan describe the
   landed behavior; and
9. no runtime or documentation surface promotes the superseded PascalCase
   selection protocol.
