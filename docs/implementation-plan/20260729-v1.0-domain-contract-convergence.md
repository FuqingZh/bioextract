# bioextract v1.0 Domain Contract Convergence

Date: 2026-07-29
Status: complete
Authority: [Domain Access Architecture](../architecture/20260729-v1.0-domain-access-architecture.md)

## Outcome

`bioextract` wraps caller-supplied official snapshots into stable,
provenance-aware resource entities, relationships, identifier resolution, and
repeatable joins. It does not know how a snapshot was downloaded or which
application consumes it.

Direct access, Parquet, and DuckDB are execution strategies:

- direct access for efficient official representations;
- Parquet for one independently useful relation;
- one DuckDB for related relations normally queried together.

The domain contract is primary. Storage conversion does not justify a resource
module by itself.

## Compatibility Decision

This is a pre-1.0 contract convergence. Superseded public names are removed
directly:

- no `*Db` aliases;
- no legacy `write_tidy()` or directory-publication wrappers;
- no deprecated keyword aliases for the naming migration below;
- stale calls fail normally with `TypeError` or `AttributeError`.

Documentation and tests describe only the final interface.

## Public Naming Migration

### Shared operation vocabulary

| Previous | Final | Scope |
| --- | --- | --- |
| `path` | `path` | every public writer |
| `result.path` | `result.path` | Parquet, DuckDB, and Rhea write results |
| `namespace` | `namespace` | selections supporting multiple identifier namespaces |
| `InputNamespace` | `InputNamespace` | generated selection output column |
| `ids_by_group` | `ids_by_group` | every `select_groups()` |
| `extract_unmatched_ids()` | `extract_unmatched_ids()` | every selection type |
| `include_source_hashes` | `include_source_hashes` | public provenance option |
| `resolve_alt_ids` | `resolve_alt_ids` | GO term selection |
| `allow_all_taxa` | `allow_all_taxa` | unscoped UniProt publication |
| `RheaWriteResult` | `RheaWriteResult` | Rhea writer result |

`destination` remains an appropriate internal variable after `path` has been
validated and converted to `Path`.

### Source path parameters

- A constructor receiving one local path uses `path`.
- A constructor accepting a directory, file, or archive uses `source`.
- A multi-file constructor uses logical resource roles without a repeated
  `file_` prefix.
- Internal storage may use role-specific `*_path` names.

Examples:

```python
GODatabase.from_obo(path)
WikiPathwaysDatabase.from_gmt(path)
UniProtDatabase.from_dat(path, source_database="sprot")

STRINGDatabase.from_files(aliases=..., links=...)
ReactomeDatabase.from_files(
    uniprot_mapping=...,
    pathways=...,
    relations=...,
)
```

Rhea constructors converge on:

```python
RheaDatabase.from_reaction_files(
    rdf=...,
    directions=...,
    relationships=None,
    obsolete_reactions=None,
    reaction_smiles=None,
)
RheaDatabase.from_compound_files(
    sdf=None,
    chebi_names=None,
    chebi_ph7_3_mapping=None,
)
RheaDatabase.from_cross_reference_files(
    xrefs=None,
    uniprot_sprot=None,
    uniprot_trembl=None,
)
RheaDatabase.from_release(source)
RheaDatabase.from_duckdb(path)
```

`from_compound_files()` names those sources by their owned compound role:
describe compound structures, ChEBI names, and ChEBI pH 7.3 mappings. Reaction
participant membership belongs to the RDF source.

### Identifier namespaces

Only selections with more than one supported identifier namespace require a
`namespace` argument.

```python
KEGGNamespace = Literal["uniprot", "ncbi_gene", "kegg_gene"]

RheaNamespace = Literal[
    "rhea",
    "chebi",
    "uniprot",
    "ec",
    "go",
    "ecocyc",
    "kegg_reaction",
    "macie",
    "metacyc",
    "reactome",
]
```

InterPro selection is fixed to UniProt and eggNOG selection is fixed to eggNOG
protein identifiers; neither keeps a one-value public `namespace` argument.

## Rhea Publication Query Contract

### Opening a publication

`RheaDatabase.from_duckdb(path)` opens a bioextract-produced Rhea publication
as a read-only domain handle. It verifies:

1. the file exists and DuckDB can open it read-only;
2. metadata v1 has the four legacy `_bioextract` tables, while metadata v2
   also requires `validation_issue`;
3. `resource_name` is `rhea`;
4. metadata and Rhea schema versions are supported;
5. the recorded table inventory matches actual `main` base tables;
6. recorded row counts match actual row counts.

Partial publications are valid. Each domain operation checks the relations it
requires and raises a clear capability error when they are absent.

Connections are short-lived and read-only. A publication-backed handle cannot
republish itself through `write_duckdb()`.

### Lazy selection, eager extraction

`select_reactions()` and `select_groups()` create immutable domain query plans.
They normalize input identifiers, validate the namespace and required
capabilities, and retain parameterized query state without materializing a
result.

```python
selection = database.select_reactions(
    ["CHEBI:15377"],
    namespace="chebi",
    include_obsolete=False,
)
```

`extract_*()` is the explicit terminal operation and returns an eager Polars
`DataFrame`. A Polars `LazyFrame` is not exposed because Polars 1.40 does not
provide `scan_database()`, DuckDB-to-Polars conversion executes the DuckDB
relation, and a native `DuckDBPyRelation` cannot outlive its connection.

If measured selection outputs require bounded-memory consumption, add genuine
`iter_*()` or direct `write_*()` terminals. Do not add a `scan_*()` that merely
wraps an already materialized frame.

### Selection entry points

```python
database.select_reactions(
    ids,
    *,
    namespace,
    include_obsolete=False,
)

database.select_groups(
    ids_by_group,
    *,
    namespace,
    include_obsolete=False,
)
```

One call uses one explicit namespace; automatic namespace inference and mixed
namespaces are not supported.

Namespace routing is:

| Namespace | Required Rhea relations |
| --- | --- |
| `rhea` | `reaction` |
| `chebi` | `reaction`, `reaction_participant`, `compound` |
| `uniprot` | `reaction`, `reaction_uniprot` |
| official external namespaces | `reaction`, `reaction_xref` |

ChEBI selection is exact in v1. `chebi_ph7_3_mapping` remains queryable in the
publication but is not an implicit conversion and is not a separate namespace.

### Extraction surface

The core selection surface is:

```python
selection.extract_matches()
selection.extract_reactions()
selection.extract_participants()
selection.extract_cross_references()
selection.extract_unmatched_ids()
```

Advanced resource-owned relations are:

```python
selection.extract_publications()
selection.extract_relationships()
```

There is no separate `extract_compounds()`. Participant extraction joins the
Rhea-owned compound identity and chemical fields callers otherwise repeatedly
join themselves.

Every matched output retains input lineage:

```text
GroupId          # grouped selections only
InputId
InputNamespace
RheaId
MasterId
Direction
...
```

Python extraction headers use PascalCase. DuckDB storage relations and derived
columns remain snake_case.

### Direction correctness

Rhea reaction sides have no substrate/product meaning without a specified net
direction. Participant extraction always retains `Side` and derives nullable
`DirectionalRole`:

| Exact direction | Left side | Right side |
| --- | --- | --- |
| `LR` | `substrate` | `product` |
| `RL` | `product` | `substrate` |
| `UN` | null | null |
| `BI` | null | null |

The publication view is `reaction_participant_direction`; it retains
`rhea_id`, `master_id`, `direction`, `side`, participant identity, and the
nullable derived role. Exact Rhea IDs are not collapsed to master IDs.

## Publication Contract

Canonical writers require an explicit `path`, stage next to the destination,
validate the complete artifact, close the database, and atomically replace the
destination only after success. `if_exists="fail"` remains the default.

Parquet provenance is embedded in footer metadata. DuckDB biological tables
live in `main`; audit metadata lives in the bioextract-owned `_bioextract`
schema:

- `_bioextract.metadata`;
- `_bioextract.source_file`;
- `_bioextract.table_info`;
- `_bioextract.column_mapping`.

No canonical publication creates a sidecar manifest.

## Verification Matrix

Automated coverage must prove:

- old names and aliases are absent from public signatures and exports;
- all writer parameters and write-result fields use `path`;
- selection namespaces and `InputNamespace` agree;
- fixed-namespace InterPro and eggNOG selections need no redundant argument;
- single and grouped selection preserve input lineage and group isolation;
- unmatched identifiers remain complete and deterministic;
- wrong-resource, incompatible-schema, missing-table, and row-count-corrupt
  DuckDB files are rejected;
- partial Rhea publications open but unsupported operations fail clearly;
- exact ChEBI matching performs no implicit pH 7.3 conversion;
- `LR` and `RL` roles are correct and `UN`/`BI` roles are null;
- exact `rhea_id`, `master_id`, and `direction` are preserved;
- Rhea extraction results agree row-for-row with direct DuckDB SQL;
- writing failure cannot damage an existing target;
- no public lazy API performs hidden eager materialization.
